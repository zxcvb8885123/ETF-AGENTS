# Agent 回測與驗證計畫 V1

## 目標與四層分工

驗證兩件事：Agent 是否能正確使用工具、依證據完成研究；它的研究是否改善扣除成本後的策略績效。研究品質與投資績效分開評估。

| 層級 | 回測責任 |
| --- | --- |
| 第一層：數據 | 提供按歷史截止時間隔離的資料與工具回傳 |
| 第二層：研究 | 使用同一份 Skill 與工具介面，讓事件 Agent 研究當時事件，接入動能候選 |
| 第三層：策略、風控與回測 | 重播決策、模擬成交、更新帳戶並計算績效 |
| 第四層：排程與報告 | 依指定設定啟動測試，輸出研究品質與績效報告 |

```text
歷史時鐘 → 受截止時間限制的資料工具
  → Agent 查詢、補查與事件判讀
  → 結構化研究結果 → 共用策略與風控
  → 模擬成交與收盤估值 → 下一交易日
  → Agent 品質報告＋策略績效報告
```

本文件為待實作計畫。每日執行與回測共用研究、配置及風控邏輯，切換資料提供者與成交模擬器。第四層只做排程與報告，不自動修改 Skill、參數或程式。

## 第一階段：先測 Agent 能否正確研究

建立人工核對的台股事件測試集，包含利多、利空、中性、混合訊息、舊聞、同名公司、缺漏及互相矛盾的公告。

| 檢查 | 測試方式 |
| --- | --- |
| 事件理解 | 比對公司、事件類型、影響方向與原始數字；使用各類別 precision、recall 與 macro F1 |
| 證據正確 | 核對引用是否存在、是否支持結論，以及無來源主張的比例 |
| 工具使用 | 缺資料時是否補查、重複消息是否合併、衝突是否揭露 |
| 不確定性處理 | 關鍵資料缺漏時是否標為待確認，而非編造或強判中性 |
| 執行可靠性 | 格式通過率、任務完成率、工具失敗率、耗時與 token 成本 |
| 權限與時間 | 工具拒絕未來資料；原文中的指令不能觸發越權操作 |

先固定測試集，再比較純規則、LLM 固定資料分析與 LLM 工具循環。事件抽取與工具使用分開評估，不能把不同任務的分數混在一起。FinBERT、社群情緒與分析師共識改列未來「市場情緒與分析師研究 Agent」的獨立評估，不納入 Data Agent 或第一版事件研究驗收。

## 第二階段：歷史交易回測

1. **固定版本**：保存資料、模型、Skill、提示詞、工具、配置及風控版本；固定工具與 token 預算，每次實驗有 `backtest_id`。
2. **按時間切分**：資料足夠時，兩年暫分 12 個月開發、6 個月驗證、6 個月保留測試。事件資料期間不足則縮小範圍並標記限制，不把缺事件當成中性。
3. **逐日研究**：D 日 08:55 決策只可使用截止前事件和 D−1 以前的完整行情。所有 Agent 工具都經歷史資料提供者，不允許直接搜尋今日網頁補歷史答案。
4. **保存研究**：記錄工具輸入輸出、證據 ID、Agent 結果、耗時與成本，再交給同一套配置及風控。
5. **成交與估值**：依競賽確認後的 D 日均價口徑模擬成交，以 D 日收盤估值。缺官方均價時標示替代假設，不以開高低收平均冒充。收盤觸發的退出最早下一交易日執行。
6. **帳戶更新**：計入雙邊手續費、賣出稅、交易單位、公司行動與現金限制；還原價不作成交價，股息不重複計入。停牌、無價格及未成交情境保存原因。

歷史補抓資料須區分「原始發布時間」「當時可用時間」與「此次取得時間」。只有可證明當時可取得的版本才能作重建依據；無法證明時標為探索資料。使用現今 150 檔回測過去需揭露交易池選擇偏差。

## 重播與 LLM 隨機性

- **保存結果重播**：使用已保存的 Agent 輸出驗證配置、帳務與績效；相同輸入應產生一致結果。
- **重新執行 Agent**：固定模型與設定，在相同歷史資料下多次執行，比較候選、交易與報酬變動；不假設 temperature 為零就完全一致，也不挑最好的一次。
- **模型記憶限制**：隔離工具無法消除模型可能記得後續事件的問題。記錄已知訓練截止資訊；歷史測試可能受污染時，另以固定版本後的前向模擬驗證。

## 比較策略是否有效

使用相同期間、成本與風控，比較固定 25 檔等權基準、僅動能、規則事件＋動能、LLM 固定資料事件＋動能，以及 Agent 工具研究＋動能。再對 Agent 版本加入防守，觀察回撤與報酬的變化。

固定資料與工具循環版本使用相同可查資料範圍和明確預算，才能判斷補查行為是否帶來改善。候選不足或風控拒絕仍列入完整時間軸，沿用既定帳戶處理規則並記錄失敗，不刪除失敗日美化績效。

| 面向 | 指標 |
| --- | --- |
| 一個月收益 | 扣交易成本後的 24 日超額報酬平均值、中位數及勝過基準比例 |
| 風險 | 最大回撤、最差 24 日報酬、個股與產業績效貢獻 |
| 可執行性 | 換手率、交易成本、成交比例、合規及可配置比例 |
| Agent 增益 | 相對固定資料 LLM 的研究改善、績效差異與額外運算成本 |
| 穩定性 | 不同時期、重跑、延後成交與較高成本下的結果 |

主要使用不重疊的 24 交易日窗口；重疊窗口僅作輔助觀察。以區塊抽樣等保留時間關聯的方法估計不確定性，樣本太少或超額報酬區間跨零時標為「證據不足」。提示詞、Skill 和參數都只能用開發／驗證資料調整；看過保留測試後修改，就需新的未見資料驗證。

## 開發與交付

1. 完成事件測試集、工具時間隔離與執行紀錄。
2. 驗證 Agent 研究品質，再完成可手算核對的帳務及成交測試。
3. 跑各版本歷史比較、Agent 重跑與固定版本前向模擬。
4. 第四層產出研究品質、工具成本、資產曲線、24 日績效、交易明細與失敗原因。

結論分為「有初步支持」「證據不足」「目前無效」。分類準確或單次獲利，皆不足以單獨證明 Agent 有投資價值。
