# 回測計畫 V1

## 目標

驗證事件策略是否能在 24 個交易日內，扣除交易成本後勝過基準；再檢查加入動能與防守配置是否改善結果。先固定測試方法，再看績效，避免只挑賺錢的期間或參數。

## 架構

```text
歷史資料庫 → 當時可見的研究快照
  → 共用策略（事件／動能／進攻與防守）
  → 共用風控與交易計畫
  → 模擬成交 → 更新現金與持股 → 收盤估值
  → 下一交易日 → 回測報告
```

| 元件 | 責任 |
| --- | --- |
| 歷史快照 | 按截止時間讀取行情、事件與基準，隔離未來資訊 |
| 回測控制器 | 逐日呼叫現有策略與風控，不另寫一套選股邏輯 |
| 模擬成交器 | 處理成交價格、數量、費稅及不能成交的情況 |
| 模擬帳戶 | 保存持股、成本、現金、公司行動與每日 NAV |
| 評估器 | 比較各版本、24 日窗口、風險與成本，輸出報告 |

## 怎麼回測

1. **固定設定**：資料與模型版本、交易池、初始資金、參數、費稅及成交方式，每次執行保存 `backtest_id`。
2. **按時間分組**：兩年資料暫分前 12 個月開發、中間 6 個月驗證、最後 6 個月保留測試。各組需要的指標暖機可讀取更早行情，但績效只計組內交易。
3. **逐日決策**：交易日 D 的 08:55 決策，價格特徵最多用到 D−1 收盤；事件必須在截止時間前公開且可取得。收盤後才知道的停損或退出訊號，最早在下一交易日執行。
4. **模擬成交**：競賽模擬採規則指定的 D 日均價，D 日收盤價只用來估值。均價口徑先核對官方定義；若確認為成交金額／成交股數，使用相同交易範圍的官方資料計算。不得用開高低收平均冒充官方均價。
5. **更新帳戶**：雙邊手續費、賣出稅、交易單位、現金與持股限制均依設定計算。除權息、分割與停牌另行處理，不能把還原價當成可成交價格，也不能重複計入股息。
6. **評估一個月表現**：主要比較不重疊的 24 交易日窗口；另外用每日起算的滾動窗口觀察穩定性。各版本使用相同起點、初始資金與暖機資料。重疊窗口不能當成獨立樣本計算信心。

缺少均價資料時只能產出清楚標示成交價假設的探索結果，不能宣稱已完成競賽口徑回測。競賽的成交假設與真實市場的停牌、漲跌停、流動性限制分成兩種情境報告。

## 比較哪些版本

| 版本 | 要回答的問題 |
| --- | --- |
| 交易池等權指數 | 是否勝過整體股票池？此為參考指數，不是符合持股檔數的組合 |
| 固定規則的 25 檔等權組合 | 是否勝過簡單持股方法？選股與再平衡規則事先固定 |
| 僅事件 | 事件訊號本身有沒有價值？ |
| 僅動能 | 績效是否主要來自股價趨勢？ |
| 事件＋動能 | 動能確認是否改善事件選股？ |
| 事件＋動能＋防守 | 防守是否降低回撤，代價是多少報酬？ |

可交易版本共用費稅、交易限制與帳戶邏輯。事件候選不足時保留「不可配置」結果，記錄失敗比例；不能暗中以動能股補滿，讓僅事件版本變質。

## 怎麼判斷有效

| 指標 | 看什麼 |
| --- | --- |
| 扣成本後的 24 日超額報酬 | 相對兩個基準的平均值、中位數及分布 |
| 勝過基準的窗口比例 | 獲利是否分散在不同時段，而非靠少數大漲 |
| 最大回撤與最差 24 日報酬 | 遇到不利行情時會損失多少 |
| 換手率、交易成本、成交比例 | 獲利是否被頻繁交易或不能成交抵銷 |
| 產業與個股貢獻 | 是否只靠單一股票或產業帶動 |
| 合規與可配置比例 | 策略能否持續產生符合競賽限制的組合 |

有效的初步證據是：保留測試期扣成本後平均與中位超額報酬為正，加入事件後優於僅動能版本，且結果在不同月份及合理成本假設下仍成立。防守效果另外比較回撤與報酬，不因回撤變小就宣稱總體績效更好。

用不重疊窗口或保留時間關聯的區塊抽樣估計超額報酬信賴區間；樣本太少或區間跨過零時，結論標為「證據不足」。兩年只有少數完整 24 日窗口，同季事件更少，不能據此保證未來有效。

## 必做檢查

- **時間洩漏**：加入未来行情或截止後事件，不得改變先前決策。歷史財報使用當時版本；後來抓取的歷史資料要標明重建假設。
- **交易池偏差**：用今日 150 檔回測過去會排除已被淘汰的公司。先標記為固定池實驗，再補歷史成分驗證，不能當成無偏的歷史結果。
- **模型洩漏**：記錄情緒模型訓練資料截止日。若未知，歷史結果標為探索性，並另做模型固定後的前向模擬。
- **情緒品質**：人工標記台股事件，分開測正／中／負分類、個股對應與新舊消息辨識。分類正確率不等於交易報酬；模型機率不是股價上漲機率。
- **帳務正確**：以可手算案例驗證費稅、現金、買賣股數、股息與 NAV；不能超賣或使用未入帳現金。
- **穩健性**：小幅調整事件門檻與持有天數，並提高成本或延後一天成交；績效若立刻消失，記錄其脆弱性。
- **避免反覆調參**：測試期只在規則固定後開啟。看完結果再改策略，該期間即成開發資料，需要新的未見資料驗證。

## 開發順序與交付

1. 補事件發布時間、歷史事件、官方均價及公司行動資料；目前日價量不足以完成事件回測。
2. 完成每日重播、模擬帳戶與可手算的交易驗證。
3. 跑基準及僅事件版本，再依策略開發進度加入動能、防守比較。
4. 產出一份報告：資產曲線、24 日績效分布、版本比較、交易明細、資料缺漏與結論。

結論只分「有初步支持」「證據不足」「目前無效」，附上測試期間、成本假設與未完成檢查。
