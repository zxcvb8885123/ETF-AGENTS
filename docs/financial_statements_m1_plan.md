## 目標與範圍

將 TWSE／TPEx 官方綜合損益表與資產負債表彙總資料保存為可驗證、可版本化的資料事實，供同一 cutoff 的 ResearchSnapshot 與事件研究查詢。Data Agent 不產生投資方向、分析師共識、配置或訂單。

本批涵蓋端點重測、業別欄位映射、資料契約、SQLite 保存、Snapshot 銜接、確定性 validator、CLI、既有 Skill 的操作說明與測試。完整 XBRL、現金流量表、附註、法說附件、歷史回補及正式歷史回測仍留在 M4。

既有 2026-09-17 來源測試記錄六種業別端點的可行性；本批須重新核實端點、欄位、期間與使用條件，不能把舊探測或 fixture 當作已完成正式接入。

## F0：來源重測與接入閘門

1. 盤點兩市場、兩種報表及各業別端點，建立來源清單與版本；實際業別名稱、端點及欄位以官方回應與文件核實後固定。
2. 保存 SourceFeasibilityReport：查詢參數、HTTP／schema、樣本雜湊、資料期間、更新頻率、使用條件、限流與失敗模式。
3. 核對公司代號、市場、報表範圍、年度／季度、金額單位及資料日期的真正意義；資料產製日不得冒充公司發布時間。
4. 每個來源先小範圍驗證，再加入核准設定；未知欄位或格式漂移必須可診斷且不能靜默採用。

驗收：每個採用來源有證據與核准狀態。缺來源或授權／保存條件不明時停止該來源，覆蓋報告保留缺漏。

## F1：資料契約與業別映射

建立 FinancialStatementRequest、FinancialStatementRecord 與 FinancialCollectionResult；名稱可依既有模組慣例調整，責任不可混用。

| 類別 | 必要內容 |
| --- | --- |
| 請求 | request ID、交易池版本／雜湊、帶時區 decision_cutoff、要求的報表種類與目標期間、來源設定版本 |
| 公司與報表 | symbol、官方代號、市場、業別格式、報表種類、合併／個別口徑 |
| 期間 | 會計年度、季度、period_start／period_end、單季／累計／時點標籤；不能證明的欄位保留缺漏 |
| 數值 | 原始欄位、標準欄位、Decimal 字串、幣別、單位倍率、缺值／不適用原因、映射版本 |
| 證據 | evidence_id、來源 URL、內容時間、published_at（可空）、available_at、fetched_at、原始回應 ID／雜湊、內容版本 |
| 結果 | run ID、逐來源狀態、逐公司／報表／期間覆蓋、寫入／重複／更正數、錯誤與限制 |

一般業、銀行、保險、證券等採獨立映射，不能把不同意義的收益硬轉為同一營收欄位。第一批只映射有明確官方定義的損益與資產負債欄位；保留未映射欄位供稽核。

缺值保持 null；不適用、未提供與解析失敗分開記錄。財報數值不是市場共識。衍生指標非本批必要輸出；若後續新增單季換算或比率，須另以確定性 Python 計算、保留輸入引用並重算驗證，不跨幣別、期間或報表範圍相減。

## F2：收集、版本與保存

- 核心放在 src/etf_agent/data/，拆分 Provider、業別 parser、collector／service、repository 與 validator；CLI 僅包裝服務。
- 先保存取得的原始回應，再解析；解析失敗仍保有 run、回應雜湊與結構化錯誤。
- 同公司、報表種類、期間及報表範圍建立穩定識別；來源與映射版本可追溯。跨端點重複資料須一致性核對，衝突時隔離，不能依回應順序覆蓋。
- 相同內容重抓不新增財報內容版本，但保留本次抓取紀錄；數值更正新增版本並連結前版，禁止覆寫舊版本。
- 有限併發與退避；每個網路請求最多三次嘗試。格式、單位或語意錯誤不靠重試掩蓋。
- 資料庫 migration 可重跑並保留既有行情、月營收、公告及 Snapshot；中斷或部分失敗不能標記全批成功。

## F3：時間隔離與 Snapshot

- decision_cutoff、available_at 與 fetched_at 必須有時區。發布時間缺漏保留 null，不能以季度結束日、法定期限或模型推測補值。
- 本批採保守可得性：新取得版本的 available_at 不早於實際取得時間；若有可靠發布時間亦不能早於發布時間。相同版本重抓保留第一次驗證可用時間，並另外保存各次 fetched_at。
- 不將今日回補倒填為歷史已可得資料。最新彙總端點不能證明當時版本，因此不能直接升級為正式歷史回測來源。
- Snapshot 只選 cutoff 前可用版本，鎖定財報版本與 evidence；更正後舊 cutoff 和已保存 Snapshot 均維持舊內容。
- 先檢查現有契約是否允許 published_at 缺漏與新增財報節點；如需升版，同步更新 builder、repository、validator、renderer 與相容性測試，不填假時間繞過舊 schema。
- 查詢需明列報表種類、期間及口徑；缺財報時標記不可用。舊研究流程可繼續使用其原有資料，但要求財報的流程必須拒絕或明確降級。

## F4：CLI、報告與研究交接

預定新增 scripts/collect_financial_statements.py，支援 database、universe、config、目標期間及 report 參數；stdout 為結構化 JSON，進度／診斷寫 stderr。以同一保存輸入重建並驗證覆蓋報告。

退出碼：0 表示要求範圍通過驗證；2 表示有明確缺漏或隔離資料；1 表示設定、執行或保存失敗。失敗時仍盡可能保存完整 run 與報告，不能只留下成功來源。

覆蓋分母固定為請求的交易池及必要報表／期間；不得把未回應、錯誤或缺資料股票移出分母。新上市、承接代號或不適用情況保留來源理由；無證據不得自行串接舊公司資料。目標期間必須明列，不能因取得某一期財報就算當期完整。

更新 event-data Skill 的入口說明與財報邊界，讓事件研究透過已驗證 Snapshot 查詢。若本批涉及 Research Report 顯示，只呈現已驗證事實與缺漏，不新增市場結論。

## F5：測試與實際驗收

離線測試至少涵蓋：

- 兩市場、各業別與兩類報表；單季／累計／時點及合併／個別口徑。
- 千元／元、負數、零、缺值、不適用及非有限數值；未知單位與期間衝突拒絕。
- 股票誤配、重複列、跨端點矛盾、來源失敗、部分成功與空回應。
- 無時區、cutoff 後才取得、更正版本、重抓去重、舊 Snapshot 不變。
- 數值、引用或雜湊遭修改；以原始回應與映射重建驗證。
- migration 重跑、CLI JSON／退出碼、報告寫入失敗、既有流程回歸。

已完成離線測試、兩市場端點抽樣核對與官方 150 檔目標期間覆蓋驗收，保存原始回應、run 與報告至 `artifacts/financial-statements/`。本次未達完整覆蓋，已明列 `3718.TWO` 的兩個阻塞項，不宣稱正式驗收完成。

修改完成後執行專案規定的 unittest、compileall、git diff --check；修改 Skill 時另跑 quick_validate.py。同步 README、Data Agent 計畫、契約與操作文件。

## 實作順序與完成定義

已依 F0 → F5 建立可重跑輸入與失敗案例：可從官方回應重建保存的財報數字、依 cutoff 選取版本、輸出同源覆蓋報告，並區分 fixture 通過與真實來源驗收的降級結果。完整覆蓋通過前，不得把本批標示為完成正式財報輸入。

本批完成後接 M1 交易狀態；完整歷史資料與回測可得性仍依 M4。建立 commit 時另依使用者指定編號及確認的 Asia/Taipei 時間辦理。
