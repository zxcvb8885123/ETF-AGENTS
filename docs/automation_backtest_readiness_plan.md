# 每日自動化與回測就緒計畫

> 建立於 2026-09-29（Asia/Taipei）。目標是在策略說明書繳交期間（2026-10-21～10-26）前，讓每日流程能無人值守穩定執行，並以可揭露限制的方式取得回測證據。

## 現況與阻擋原因

### 每日自動化

2026-09-28 共執行四次 `scripts/run_daily_pipeline.py`：

| run | 結果 | 原因 |
| --- | --- | --- |
| `daily-20260928` | failed | 虛擬帳戶尚未開帳，`latest.json` 不存在 |
| `daily-20260928-163158` | failed | `./start.sh daily` exit 2 |
| `daily-20260928-164128` | completed | Decision run `decision-20260928T084128Z` approved、30 筆買進 |
| `daily-20260928-192156` | 停在 `running` | 程序中斷後沒有收尾，摘要未更新 |

結構性問題：

- 是否執行、帳本 T+2 交割日仍以週一至週五近似；官方開休市日曆只用於交易狀態包的目標時段。
- 中斷的 run 停在 `running`，沒有逾時判定或標記。
- 每次 20～40 次 `claude -p` 呼叫，撞到用量上限只能人工 `--resume`。
- launchd 樣板未安裝；Docker Desktop、`claude` 登入、Mac 未休眠都沒有事前檢查。

### 回測

`artifacts/backtests/agent_readiness_2026-08.md` 顯示 2026 年 8 月 0／21 日可執行：沒有逐日 Snapshot、沒有版本化交易狀態、官方行情未覆蓋完整交易池。即使補齊，模型可能記得後續事件，且每個交易日需 20～40 次 Agent 呼叫。原本決定比賽前不做 Agent 歷史重跑；2026-09-29 改為執行[回測重放計畫](backtest_replay_plan.md)，先以 8/21 單日重放驗證架構可行性。

## 階段 0｜2026-09-29 手動執行

- 收盤資料公布後執行 `.venv/bin/python scripts/run_daily_pipeline.py`；會先以 9/29 官方收盤價結算 9/28 決策，再產生下一次決策。
- 撞到用量上限時執行 `--resume --skip-data`。
- 檢查 `pipeline.json` 與帳本的成交／未成交數；部分成交保留作 A4 測試案例。

| C1 前向模擬 | 虛擬帳本即真實前向回測；每日以同一 Snapshot 另跑等權與純動能基準，交給 B3 比較器 | 可立即進行。至 10/20 約 15 個交易日，未滿一個 24 日視窗，固定標示 `insufficient` |

## 進度

- A1（2026-09-29 完成）：新增 `etf_agent.data.trading_calendar.TradingCalendar`，由封存的 `TWSE_CALENDAR_OGD` 建立並驗證原始檔雜湊；每日流程改以日曆判斷是否執行（找不到日曆時停止並通知），交易狀態包目標時段檢查年度涵蓋，帳本 T+2 改用日曆並記錄日曆雜湊，移除未使用的 `next_weekday_session`。以真實封存驗算：9/29 交易日、10/9 與 10/26 休市、10/8 的 T+2 為 10/13。限制：日期表只涵蓋 2026，12/30 起的 T+2 會跨入 2027 而停止，需等證交所公布 2027 日期表。
- A3（2026-09-29 完成）：新增 `etf_agent.automation.preflight`，每日流程在抓資料與呼叫子 Agent 前依序檢查 Docker daemon（`--skip-data` 時略過）、`claude auth status` 登入、虛擬帳戶最新狀態完整性、必要設定／資料庫／`.venv`（`--skip-data` 另需既有 Snapshot 與帳戶快照）、可用磁碟空間；全部結果寫入 `pipeline.json` 的 `preflight`，任一失敗即停止並通知。外部指令逾時 30 秒，不記錄登入帳號。`--preflight-only` 可單獨執行。收盤價是否公布不另做時間判斷，仍由資料階段與帳本 `settle` 的 `waiting_for_close_data` 在 Agent 前停止。
- A4（2026-09-29 完成）：原規劃把部分成交缺口告知交易 Agent，但使用者確認比賽是模擬交易、合規委託一律成交，部分成交只是本專案帳本的量能假設，因此改為修正帳本：`OfficialCloseMarket` 以官方成交金額 ÷ 成交股數（ROUND_HALF_UP 0.01）作成交價、`available_lots=null` 不設量能上限，日終仍以收盤價估值；`ExecutionSimulator` 只在明確給整數時才套量能上限，買力限制不變。以真實 9/24 資料驗算：2330 均價 2480.31（收盤 2475）、6488 均價 941.90（收盤 948）。風險審查另收到 `sector_exposure`（各產業實際權重、上限、剩餘空間與成分股），不改變 Guard 輸出，既有封存 run 的重建驗證不受影響。未改：`liquidity_stress` 情境仍以 50% 成交率做壓力測試（只記警告）。
- 2026-09-29／30 實跑後的修正：(1) 上市當日行情（證交所 `STOCK_DAY_ALL`）到 23:04 仍晚一天，官方個股日線補抓改為可到任一市場已公布的最新交易日並加進每日流程，9/29 收盤資料當晚即可結算；(2) 用量上限或跨午夜後日期已變，新增 `run_daily_pipeline.py --resume-run <run_id>` 指定續跑前一天的 run；(3) 已持有的股票在決策前被限制交易（9/29 精材 3374.TWO 被處置）會讓 Guard 的情境否決整份決策，導致不論給什麼決策都被拒，改為只能續抱、以 `HELD_NOT_TRADABLE` 警告通過（買賣受限股票仍被擋）。9/29 實跑：9/28 的 30 筆委託全部成交、淨值 996,158,821；9/30 決策為核准的不交易（0 筆委託），完成時已超過 9/30 08:55 送件時限。
