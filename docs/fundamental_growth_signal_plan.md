# 基本面成長訊號：現況說明

## 這是什麼

基本面分析師要分辨「真的在成長」與「只有一個不能跨股比較的訊號」。這份文件說明已經做了什麼、還沒做什麼，以及為什麼。

## 當初發現的問題（2026-10-28 的 run）

| 現象 | 數字 |
| --- | --- |
| 基本面判斷偏多 | 150 檔中正面 83、中性 57、負面 9；技術分析師則是負面 57、中性 48、正面 44，會分辨方向 |
| 程式算得出的成長指標很少 | 營收年增只有 7 檔、稅後淨利年增 5 檔有值；143 檔缺「去年同期損益表」 |
| 金融業一個比率都算不出來 | 金控 12 檔、銀行 4 檔、證券 1 檔 |
| 月營收年增 150 檔都有 | 所以分析師不是看不到成長，而是只剩這一個訊號 |

最明顯的是 7 檔金融持股（2801、2880、2884、2885、2886、2890、2891）：依據實際上只有月營收年增，卻得到正面。分析師對缺口很誠實，每檔都寫明沒有去年同期可比資料；問題在於制度允許單一不可比訊號撐起正面。金融業的月營收含保費與手續費收入，會計內容和製造業的營業收入不同，波動又大（例如 2885 累計年增 105%），和半導體並列比較會高估金融股。這也是持股前幾名偏金融股的上游原因，配置端的低波動偏好是下游放大器（見[配置與輪動 v2](sizing_rotation_v2_design.md)）。

去年同期資料缺的原因是流程缺口，不是額度用完：當天紀錄只寫「FinMind 連線失敗」，「額度用完」只是訊息樣板裡的舉例，沒有證實。

## 現況

| 項目 | 狀態 | 說明 |
| --- | --- | --- |
| 成長訊號品質標記 | 已實作 | 程式替每檔股票判定三種等級，放進基本面分析師的摘要：可比（有同口徑財報算出的營收或淨利年增）、只有月營收（缺去年同期損益表）、產業公式不支援（金融業等，連當期比率都算不出來）。每檔附說明文字與缺漏原因 |
| Skill 說明 | 已實作 | 基本面分析師的 Skill 已寫明：月營收年增單獨不足以判斷獲利改善，金融業月營收不能與一般業比較；品質不是「可比」時，須在理由中說明受到什麼限制，並把缺少的期間與報表列為缺口 |
| 金融業與其他業別去年同期補抓 | 已實作，但不在排程內 | 補抓指令已支援一般業、其他業、金控、銀行、保險與證券期貨；金融業只補稅後淨利，營收類項目口徑不同，刻意不接入。細節見[基本面缺口補抓](fundamental_data_repair.md) |
| 強制規則：品質不可比時不得判正面 | 尚未接入 | 目前標記只提供事實，正面、中性或負面仍由分析師依既有標準判斷，Validator 不擋。原因是一旦硬擋，大量股票會變中性，買進候選可能少於 30 檔，被持股下限擋住，需先用實跑或影子回放評估候選數 |
| 補抓納入每日排程 | 已實作（2026-11-10，尚未在排程環境實跑確認） | `start.sh` 在 FinMind 候選擷取後呼叫 `cli/fundamental_repair.py --scheduled`：只補官方最新期別尚無去年同期文件的股票，每輪有檔數上限，`PRIOR_REPAIR=0` 可關閉，失敗只降級。核對規則與時間規則不變；7828.TWO、3718.TWO 仍補不了。見[基本面缺口補抓](fundamental_data_repair.md) |

## 效果與判讀

- 標記讓分析師與後續讀報告的人，一眼看出哪些成長訊號可跨股比較。它不改變任何股票的判斷結果，也不是硬規則。
- 是否要把「不可比就不得判正面」升級成 Validator 規則，應先累積幾天標記分布，再決定先要求說明缺口，或直接禁止。
- 金融業要有可跨股比較的指標，需另外定義專用指標（淨收益年增、利息淨收益、費用收入比），目前沒有這項工作。
