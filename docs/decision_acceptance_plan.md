# P6 決策驗收與風控補強計畫

狀態：fixture 驗收已完成（2026-09-21）。A1～A5 已落實於契約、確定性引擎、完整修正鏈、CLI 與測試；正式帳戶、競賽規則及交易狀態 Provider 尚未接入；基準 Provider 僅供選配比較，因此可交付 P7 回測開發，但不能宣稱正式資料端到端完成。

## 目標與現況

建立可手算核對、可完整重播、無法跳過上游驗證的模擬決策流程，交易單位固定一張 1,000 股。沿用現有 14 個 Skills，本階段主要補強 Python、契約、CLI 與測試，不另加新的研究 Agent。

P6 已完成下列契約補強：

- `ScenarioEngine` 依實際成交張數重建持股、現金、費稅與 NAV；啟用基準比較時才另算 Active Share。
- `RevisionHistoryValidator` 從 revision 0 重播每次合法修正，Finalizer 只接受最後一版。
- Guard 使用規則內獨立的必備基準名單；硬規則內容、來源、時間與雜湊均被綁定。
- Repository 會驗證磁碟上每份 artifact、manifest 與檔案集合；CLI 情境、Guard 與 Risk 入口均驗證相同上游鏈。

## A1 規則、輸入與信任邊界

交付：版本化 RulesBundle、執行假設與策略設定邊界、統一驗證入口。

- 將不可由策略放寬的硬性規則與可修正策略參數分開；規則版本、來源證據、available_at、內容雜湊需與 DecisionInputBundle.rules 一致。
- 若另行啟用 Active Share 比較，明列基準 ID、版本、持股範圍及計算口徑；缺資料只停用該比較，不阻擋競賽個股上限。官方口徑在實作時查核正式文件，未核實時僅能使用標示清楚的測試規則。
- 帳戶 NAV 與 cutoff 行情估值做對帳，明確區分原始帳戶估值日期、重新估值 NAV、可用現金及未結算資金。
- 統一驗證整數、布林、有限數值、上下界、重複代號與未知欄位，禁止 float/bool 被轉型成合法股數。
- 每個配置、情境、Guard、修正、封存入口都驗證必要上游；檔案可解析或 hash 正確不等於 artifact 合法。

驗收：放寬 policy 不能改寫硬性規則；刪除已啟用基準、未來版本、錯誤 NAV、未知欄位及非法型別均被拒絕。

## A2 整張配置與金額正確性

交付：可手算的配置／費稅案例、金額精度政策與獨立不變量檢查。

- 買進、加碼、減碼與退出都使用整數張；lots 與 shares 必須嚴格一致。依目前約定，帳戶含零股直接停止。
- 明定不足一張的減碼不偷偷升級為全部退出；不足一張買單保留限制原因。
- 價格與金額保留足夠 Decimal 精度；只在設定指定的費用／結算邊界進位，避免參考價格被顯示取整後無法核對。
- 以帳務恆等式驗證期末持股、現金、費稅與 NAV；費率、最低費用、進位方式版本化。
- 核對配置政策是否符合計畫的等額分配、上限裁切及剩餘資金分配；個股特殊上限、產業上限與風險修正必須一致生效。
- 退出／減碼不能為滿足換手上限被悄悄取消；不可行配置明列原因。

驗收：至少覆蓋 1／2／3 張減碼、完整退出、最低手續費、含小數價格、現金差一元、賣出資金不可立即使用，以及特殊個股上限修正。

## A3 真正重建壓力情境

交付：从原始帳戶與情境成交明細重建的 ScenarioResult。

- 將成交率、滑價與收盤價格衝擊分開設定，不以滑價倍數直接推導成交率。
- 模擬完整、部分及零成交；部分成交數量仍為整張，保留未成交張數。
- 每個情境依成交明細重新算持股、費稅、結算／可用現金、NAV、個股／產業權重，啟用比較時才計算各基準 Active Share。
- Guard 對所有必要情境重新檢查硬性規則，包含賣單未成交卻執行買單造成的資金缺口。
- 交易可行性同時检查訂單與結果持股，不能因標的預計退出就漏掉不可交易狀態。

驗收：零成交恢復原帳戶部位；部分成交帳務可手算；強制退出未成交、現金不足及情境超限不能核准。

## A4 完整修正鏈與最終裁決

交付：RevisionHistory 契約、重播 validator 與最終狀態測試。

- 首次提案從原始 policy 重建，不接受未經審查的 overrides 或排除清單。
- 每筆修正保存前次 Proposal／Scenario／Guard／RiskReview、允許動作、下次提案及內容 hash。
- Validator 由第 0 版逐步套用修正，檢查父子關係、連續序號、政策收緊方向與最多三次上限。
- 硬性失敗只能拒絕；Risk 不得對失敗 Guard 提出修正以繞過停止條件。
- 最終 approved／no_trade 必須對應最新版本的有效審查；rejected 保存具體拒絕原因，最終可用訂單為空。

驗收：跳過歷程、偽造 parent、重設次數、第四次修正、舊審查套新單、直接改 effective_policy 均不能通過。

## A5 保存、CLI 與端到端驗收

交付：可驗證的完整 run、CLI 整合測試與 P6 驗收紀錄。

- 封存原始輸入、所有修正版本、最終結果與 manifest；重跑需驗證磁碟內容，不能只比 manifest。
- 限制 run ID 與 artifact 檔名，測試路徑越界、缺檔、內容竄改、中斷與重複保存；不覆蓋不同內容。
- 驗證 CLI 實際參數、退出碼與檔案輸出，包含 validate-risk 的必要參數一致性；提供完整 fixture 操作範例。
- 用獨立手算結果驗證帳務，不只以同一個 engine 重算比對自己。
- 執行全專案 unittest、compileall、diff 檢查；有修改的 Skills 執行結構驗證。
