# 決策流程細節

這份文件說明每日決策「為什麼這樣做」以及幾個關鍵規則的現況。整體流程見[根目錄 README](../README.md#決策流程)，各步驟的完整契約見[每日決策架構](architecture.md)，換股與權重的做法見[配置與輪動](sizing_rotation_v2_design.md)。

## 基本原則

| 原則 | 意思 |
| --- | --- |
| 分工 | Agent 只提出有證據的市場解讀、買賣意圖與信心；指標、權重、股數、費稅、現金與競賽限制全由程式計算與驗證。 |
| 時間一致 | 所有下游輸入都要和研究快照的截止時間、資料版本一致，只用當時已經拿得到的資料。 |
| 失敗就停 | 資料不足或風控不過時，停止或明確降級，不填假值。 |
| 前次決策只是背景 | 交易 Agent 看得到上一個交易時段交出的決策（對現有持股的意圖、信心、重估條件），用來檢查這次判斷是否一致。它不是證據，不能當理由；行動仍要由當天的多空論點支持。同一時段的晚間備案不算前次；跨快照會明確標為例外；沒有前次決策就標為無資料。 |

## 參賽策略文件的因子怎麼落實

交給主辦方的策略文件（`game_docs/ETF-AGENTS_AI_Agent_選股與決策策略_參賽格式.pdf`）寫了四類因子，數字全由程式算好再交給 Agent，細節見[架構文件](architecture.md#對應參賽策略文件的四類因子)。

| 因子 | 做法 |
| --- | --- |
| 基本面 | 營收、獲利、負債，加上現金流（FinMind 現金流量表，稅前淨利與官方損益表相符才採用）。 |
| 技術 | 5／20／60 日變化、MA20／MA60、ATR 與下行波動。 |
| 公司事件 | 每則事件要寫影響、反證與尚待確認的事項。 |
| 市場與風險 | 風險 Agent 讀整體市場情緒、產業集中、每筆委託占 20 日均量的比例與壓力情境。比賽以成交均價結算，成交量只當提醒，不限制成交。 |

## 持股怎麼挑、怎麼配

### 持股檔數

風險 Agent 在給現金姿態時，同時選一個持股廣度，程式再換算成檔數。Agent 自己不輸出檔數。Policy 開啟 `cash_ratio_range` 時，風險 Agent 另選姿態內子等級 `cash_grade`（lower／middle／upper），現金比例由格點對應，Agent 同樣不輸出百分比（見「控制回撤」一節）。

| 廣度 | 檔數 |
| --- | --- |
| 集中 | 22 |
| 平衡 | 26 |
| 分散 | 30 |

程式照交易 Agent 的信心由高到低挑到該檔數。同信心內的先後，現行做法是交易 Agent 在各批合併後另做一輪排序（見下節）。

### 入選排序

交易 Agent 是分批平行執行的，各批看不到彼此的候選，所以每批只能給高、中、低三級信心。同一級裡誰先入選，由交易 Agent 在各批合併後再做一輪，一次看完全部買進／加碼候選，只在同級內排先後並附理由，不改信心、不輸出數字。每一級都只有一檔時不呼叫 Agent，程式直接封存。

### 低波動偏好

權重 = 信心等級乘數 ÷ 波動度的若干次方。次方是 `volatility_exponent`：1 代表完全依波動度反比（舊做法，低波動股權重可到高波動股的 4～5 倍），0 代表同信心等級內等權。目前正式設定為 0。這個值與「單次換股上限」可由策略反思依校準報告微調，版本開關只由人設定。

份額與單股上限：原式只把單股上限當封頂，台積電上限 25% 對份額沒有作用。版本閘門 `position_sizing.limit_scaled_conviction`（`{"version": "v1", "alpha": "0.6"}`，alpha 必填、由人設定，**目前正式設定已開啟**）讓高信心股的份額至少為 alpha × 該股單股上限（再以封頂為限）；原式份額已高於這個下限時照原式；預算足夠時，高信心股不會因為別檔被抬高而少於原式份額。必要份額（原式與下限取大）總和超過預算時，依入選名次填到預算用完，中低信心為 0。`volatility_exponent` 為 0 時，中信心不高於最小的高信心、低信心不高於最小的中信心（例如 2330 為中信心時）；因此分不完的預算留作現金。前提是 `conviction_volatility_v2` 與 `selection_ranking`。公式、預算守恆與封頂見[計劃檔的「α 方案」](limit_aware_conviction_weights_plan.md)。proposal 的 `position_sizing` 區塊只在開啟時記錄 `limit_scaled_conviction`。

### 滿檔換股

持股已達上限時，沒持有的新股只能用「本次有人出場」釋出的名額。每次最多換幾檔、新股至少要多高信心，由設定決定（現為最多 5 檔、至少中等信心）。誰換誰由程式全域配對；交易 Agent 只看到程式算好的名額狀態當背景，不指定誰換誰。出場必須有該股的空頭論點或持股檢視警示支持，不能為了騰名額而賣。

另有「強制換股」：持股滿檔又沒人出場時，高信心的新股可換掉「交易 Agent 標為續抱、且每週論點檢視判為已被推翻」的持股，每次最多 2 檔，且必須有交易 Agent 採納的該股空頭論點。

### 持股檢視（停損／停利）

程式依帳戶成本與行情，算每檔持股的帳面報酬與近 20 日高點回落；達到人設定的門檻就標警示。目前只設了「虧損達 15%」一條，回落與停利門檻都未設（不設死數字）。警示不是賣出指令，交易 Agent 必須正視並自己判斷賣、減碼或續抱；虧損警示的持股要續抱，須同時有多頭論點。比賽開帳或重建日的成本是當日收盤價，不是真實買價。

### 證據要支持結論

多空論點與分析師發現必須宣告種類（價格、財務、營收、重大事件、新聞），程式核對引用的證據種類是否對得上，且至少一個證據要屬於該股票；市場層級與帳戶證據只能當補充。風險 Agent 的現金姿態至少要引用一個市場層級證據，全市場情緒負面時不得選積極。驗證被退回時，回饋同時列出「降級」與「補依據」兩種修法，重試前後的差異記在執行紀錄。

### 控制回撤

目前數值以 [status.md](status.md#版本閘門啟用狀態) 為準（2026-11-11 12:36 起強制防守線為 15%／11%，原 10%／7%）。程式用帳本的淨值歷史算帳戶從峰值回落的幅度，用來限制現金姿態與主動降低曝險。

| 回撤 | 現金姿態下限 | 解除條件 |
| --- | --- | --- |
| 達 5% | 至少中性 | 回到 3% 以下 |
| 達 15% | 至少防守 | 回到 11% 以下，降回中性 |

防守姿態下，程式會依 ATR 由高到低主動減碼（`held_weight_budget: "v1"` 另讓「現有權重已高於信心份額」的加碼候選不再加碼、以現有權重計入預算，避免新股被超配後又被現金緩衝砍；`drawdown_derisk.version: "v4"`（現行正式設定已升 v5，減碼順序由交易 Agent 給，見 status.md）在 v3 之上把減碼額度限制在「換手上限減去交易 Agent 賣單」的餘額內，目前正式設定兩者皆已開啟，2026-11-08 起），直到現金達姿態緩衝（目前 20%；開啟 `cash_ratio_range` 時為所選子等級的比例），單次最多減 NAV 的 25%。`position_sizing.drawdown_derisk.version`（只由人設定）：v1 整張進位可超過單次上限，且交易 Agent 標 add 的同一檔會被加回原持股（留下 `RISK_DRAWDOWN` 旗標卻沒有賣單，現金也達不到緩衝）；v2 進位不得超過上限；v3 另把被減碼的持股排除在本次加碼候選外，減碼後的股數就是上限、不建買單，交易 Agent 的意圖仍保留為 add。舊版本的決策逐位元維持原重建。開啟 `high_conviction_cash_floor`（版本閘門，目前未開啟，須 `cash_buffer_floor`、`cash_fit_order` 與 v3）時，觸發與目標改為「緩衝 × floor_ratio」（例如防守 15%），與高信心買單可動用到的下限相同：20% 以上全部自由、15%～20% 只有高信心能動用原有現金、低於 15% 才由程式減碼補到 15%；當日觸發減碼時高信心也以完整緩衝計，`RISK_DRAWDOWN` 的說明文字改寫軟下限。設定綁定時會一併記下帳本歷史的指紋；每日流程與事後重建都用帳本歷史重算並比對峰值，被竄改就拒絕。

姿態內現金子等級 `cash_ratio_range`（版本閘門，目前正式設定已開啟，與 `high_conviction_cash_floor` 互斥）：現金比例 = `grid[姿態][cash_grade]`。單日只限制現金拉高，今日可選格點 ≤ max(該姿態 lower, 前次比例 + `max_daily_raise`)，往下不限；以建議格點與 3pp 為例，前次中性 10% 轉防守的第一天只能選 15%，隔天最多 18%，再隔天 21%。回撤強制防守時同樣只到防守 lower，不放寬。前次比例 `anchor` 取自前次決策 run 的最終現金緩衝（與交易 Agent 的前次決策背景同一個 run），沒有前次 run 時用本次起始現金比例；它只給風險 Agent 當背景、不可引用（風險理由出現前次 run_id、decision_id、proposal_id 或其內容雜湊即拒絕，含 decision_id／proposal_id 不帶前綴的完整 20 位摘要；比對有邊界，前後接 ASCII 英數或底線的較長 ID 不算，不封鎖 run_id 片段、日期或短雜湊；decision_id 取自同一份前次決策背景。驗證錯誤中由 Agent 提供的外來值（如不存在的 evidence_id）會去換行與控制字元、限 80 字並加引號，重試回饋每則錯誤另壓成單行、限 1000 字）。選了今日不可選的子等級即退回重答，修正循環用盡即停止，程式不夾到邊界。事後以 `cli/portfolio_decision.py` 執行 finalize／validate-decision 時，閘門開啟的 run 會讀預設決策庫 `artifacts/decisions` 重讀前次 run；也可以用 `--decision-repository` 指定其他位置。沒有閘門的舊 run 不讀決策庫。

配置後風險審查的修正動作 `increase_cash_buffer`（2026-11-05 起，不論有沒有閘門）：值必須不高於競賽現金上限 `cash_weight_ceiling` 減 3 個百分點邊際（比賽上限 25% 時最高 22%；邊際為 `decision/risk.py` 的 `CASH_BUFFER_CEILING_MARGIN`，上限一律取 Policy），否則該審查無效，退回風險 Agent 重答。緩衝達到上限時，修正後的提案必然被 Guard 的現金上限拒絕，之後的修正又不得再降低緩衝，等於把當天推向拒絕；即使低於上限，整張取整與現金分配仍會讓現金高於緩衝（例如起始現金約 21%、緩衝 24% 時現金到 25.12%），所以要留邊際。留了邊際仍超過上限時，照舊由 Guard 拒絕。

## 交割與現金（2026-11-03 起）

| 規則 | 做法 |
| --- | --- |
| 賣款當日可用 | 主辦方是淨額交割，所以規則檔改為賣出收入可買同日替補。規則封存在每份決策裡，舊 run 仍以當時封存的規則重建。 |
| 現金不足的買單順序 | 信心高、名次前的先拿錢。沒持有的新股若只買得到目標的一半不到，整筆取消（不讓 1～4 張的零頭占名額）；已持有的加碼則只減量。 |
| 現金超過 25% 上限 | 程式依 ATR 由低到高，留住交易 Agent 想出場的持股，直到現金回到上限內，不再整份拒絕。沒有可留的出場時，仍由 Guard 拒絕。 |
| 單股上限留空間 | 當日有買進／加碼的股票，上限只用 97%（一般 10%、2330 為 25%）；只續抱的留 0.5%。自己買超限當日就算違規，價格漲到超限才有 5 日寬限。 |
| 跳空預留 | 決策用前日收盤、成交用當日均價，所以買單總額多算 3% 當現金需求，避免開高後被主辦方以資金不足整批作廢。 |
| 結算口徑 | 主辦方資料包顯示前一日委託被作廢時，帳本把該日結算為無成交；模擬成交若現金不足也整批作廢（與主辦方一致）。 |

## 單股超出權重上限時

既有持股若因價格上漲超出單股硬上限：

1. 程式在 Guard 之前，按整張算出必要的減碼。
2. 連同部分成交的壓力情境一併重算。
3. 交易 Agent 的原意圖與程式的風險減碼分開記錄；減碼的賣單由程式標為減碼（仍有持股）或出場（減至零）。
4. 仍無法滿足所有硬性限制時照樣拒絕。

## 單一產業超過 60% 時

產業上限不是比賽規則，是本隊自設的風控，目前為 60%（11/03 白天曾關閉，更早為 35%；舊 run 以封存的規則重建）。程式在 Guard 前檢查各壓力情境下的產業權重：

- 現行做法：超標時只按整張減少當日買進／加碼的增量（同產業先減信心低、市值大者），**不賣既有持股**。買單減光後仍超限（價格漂移造成）的產業，Guard 會容忍，條件是本次沒有買進該產業的任何股票；有買進的產業仍算硬性違規。
- 沒有啟用這項設定的舊路徑：先減當日買進，再賣既有持股，Guard 嚴格判定。
- 減碼會留下標記，並且釋出的資金不再拿去加碼其他股票。

## 其他風控（2026-11-03 晚間）

| 規則 | 做法 |
| --- | --- |
| 換手上限 30% | 換手 = 買賣金額合計 ÷ NAV。超過時先縮減買單：加碼只減增量，新股殘量不到目標一半就整筆取消；賣單本身就超過時，依 ATR 由低到高留住出場持股，不整份拒絕。 |
| 出場後冷卻 3 天 | 最近 3 個日曆天內出場（含強制換股）的股票，若目前未持有就不再買。名單由每日流程從決策庫帶入。 |
| 強制換股要有證據 | 被換出的持股，必須有交易 Agent 本次採納的該股空頭論點，否則不換。換出檔數也不能讓持股低於最少檔數，且現金要付得起新股。 |

## 版本相容

以上 2026-11-03 起的規則，以及持股檢視、入選排序、換股等，都是只由人設定的版本開關，策略反思不得更動。沒有該開關的舊設定與舊 run，重建結果與當時逐位元相同。分析團隊輸入的版本也一路向上（2.3 加名額脈絡、2.4 加持股檢視、2.5 加入選排序、2.6 加逐檔基本面指標），Finalizer 整份重算比對；最新一批決策已使用 2.6。
