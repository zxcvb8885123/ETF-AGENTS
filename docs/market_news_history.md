- 這是用途與使用權問題，不是資料取得的缺口。

**怎麼處理**

- 正式比賽資料包仍維持既有 `approved` 規則。
- 不以 RSS 的有限使用條款，宣稱取得全部原頁、全文或其他用途的授權。
- 報告把「本地研究看法」和「正式比賽通道狀態」分開。診斷結果不能改寫成已核准的正式結果。

## 重複執行

```bash
.venv/bin/python cli/market_news.py backfill \
  --start-date 2026-10-01 --end-date 2026-10-03 \
  --database var/etf_agent.db \
  --output-root artifacts/market_news_history
```

核心收集器在 `perception/market_news/history.py`，限制如下：

- 只連公開主機。
- 限制原頁路徑、日期視窗、分頁與回應大小。
- 跟隨實際的下一頁，中文網址會編碼。分頁若改動日期或來源，一律拒絕。
- 保存目錄、原始回應，以及分頁是否走完。
- 網路失敗時不宣稱完成，也不補零或補假新聞。

## 資料包 1.1

- 同時接收 RSS 與歷史原頁。
- 原頁內容由 metadata 重建，必須有：帶時區的 `published_at`、實際的 `available_at`、標題、原始內容雜湊。
- 新增來源種類不會增加媒體數。
- 舊 1.0 成對輸入維持原版本的重建結果，封存內容不改寫。
- 新的 1.1 不再固定加入「RSS 不涵蓋全部歷史」缺口，改為描述實際收集範圍。

### 時間點限制

今天取得的原頁可能已被更新過。

- `available_at` 保留為今天，不能冒充過去就已存入系統。
- 不能用目前版本，加入取得日之前的正式回測。
- 真正的歷史回測，需要當時的內容版本與可得時間證據。只把 `published_at` 改成當年日期不行。
