# 文獻對照、專案改進與論文計畫

狀態（2026-11-17 晚）：**只是計畫，沒有改任何程式、設定或其他文件**。比賽 11/27 結束，目前有 16 個已結算交易日（10/27～11/17），剩 8 個。

本文每段都標示性質：

- **事實**：我在本專案的檔案或指令輸出裡實際看到的，附檔案位置。
- **已抽查**：我開了 arXiv 摘要頁核對過（只有摘要，沒有讀全文與表格）。
- **二手**：來自四份上網研究（只讀搜尋摘要），我沒有核對；數字引用前必須回原文。
- **推論／意見**：我的判斷，不是證據。

## 0. 先講結論

1. 這套系統最站得住的東西是**紀錄方式**，不是績效：每天的輸入、Agent 原始輸出、驗證結果、程式配置都封存且可重算，而且有主辦方資料包每天對帳。近年文獻批評 LLM 交易論文的幾個主要問題（未來資訊洩漏、短回測、沒算成本、挑結果），這套系統在設計上大多已經避開。
2. 績效不能當賣點。到 11/17 帳戶 -8.49%、0050 買入持有 -11.99%、150 檔等權 -15.80%（`cli/benchmark.py compare`）。但帳戶對 0050 的實現 beta 只有約 0.42，贏的幅度與「曝險比較低」一致；扣掉曝險後每日 alpha 是負的、不顯著（第 2.2 節第 4 項）。**目前的資料不支持「選股有效」，也不支持「選股無效」。**
3. 最大的三個缺口：沒有消融實驗、沒有統計區間、設定在比賽中途被人改了很多次（`config/policy_versions/` 有 42 個樣板，全在 11/09～11/17）。第三項事後補不回來，只能如實揭露。
4. 比賽結束前只建議做「多記錄、不改決策」的事，優先三項：記下完整模型識別碼、把 `artifacts/daily/` 與資料庫完整備份、在比賽結束前把論文要報的指標先寫死。
5. 論文定位為「有即時稽核紀錄的系統與經驗報告」，先上 arXiv。不宣稱贏市場。即使最後名次不好，貢獻點仍然成立。

## 1. 文獻要點與證據評級

評級定義：

- **獨立驗證**：非原作者重測，且經同儕審查。
- **同儕審查實證**：有實驗、經審查，但由原作者提出。
- **作者自報**：預印本或原論文自己的績效數字，沒有他人重測。
- **官方建議**：廠商的工程文章，含廠商自測。
- **意見**：立場文、部落格、工程經驗談。

### 2.2 缺口

**1. 完整模型識別碼沒有封存**

- 文獻：Alpha Illusion 要求揭露模型版本與知識截止日（二手，對應細節未核對）。
- 現況（事實）：`pipeline.json` 的 `agent_calls[].model` 只有別名 `sonnet`、`opus`；`agent_cli_versions` 只有 CLI 版本（`2.1.326`）。別名指向的模型可能在比賽期間換過，目前無法證明沒換。`grep` 找不到任何讀取完整模型識別碼的程式。
- 建議：在執行紀錄多存 CLI 回報的完整模型識別碼。做法比照 `skill_digest.py`：只加在 `agent_calls`，不進任何決策 artifact 與雜湊。要先確認 CLI 的輸出事件裡確實有這個欄位，我沒有查。已經跑完的 16 天補不回來，論文只能寫「別名加 CLI 版本」。

**2. Agent 實際讀了哪些檔沒有記錄**

- 現況（事實）：指令只存雜湊，內容要靠程式版本加 `brief_*.json` 重建；`*_raw_N.json` 只有輸出（我看了 `cash_stance_raw_1.json`）。Agent 有 `Read` 工具，除了拒讀清單以外的專案檔都讀得到，實際讀了什麼沒有留下紀錄。
- 影響（推論）：無法排除 Agent 讀到簡報以外的檔案，例如舊 run 的結果或計畫文件裡的事後分析。Claude 的拒讀樣式擋了舊 run 的多空輸出，但擋不了 `docs/`。
- 建議：賽後把串流輸出裡的工具呼叫路徑存成執行紀錄；比賽中不動。論文把它列為已知限制。

**3. 沒有消融實驗**

- 文獻：研究摘要稱只有 FinCon 做過風控與反思的拆除實驗，辯論沒有乾淨消融（二手）；Alpha Illusion 的「多 Agent 拆解」要求對照單 Agent。
- 現況（事實）：`evaluation/service.py` 可以用封存的 `decision_input.json` 重跑，只有 `--stop-after analysts` 這種截斷，沒有「拿掉某個 Agent」的開關（我搜尋 `ablat`、`variant`、`disable` 沒有結果）。
- 建議：賽後做，設計見 4.5。

**4. 沒有統計區間與檢定**

- 文獻：Lo（2002）、Deflated Sharpe（未對照原文）。
- 現況（事實）：`benchmark/tools.py` 只有累積報酬、最大回撤、相對回撤；`evaluation/replay_tools.py` 的 Sharpe 少於 20 個日報酬就標不可用。沒有 bootstrap 或 HAC。
- 我用 `cli/benchmark.py compare --json` 的逐日表粗算（16 個日報酬，一般 bootstrap，沒有處理序列相關，**只是示意，不是正式結果**）：

| 對照 | 每日超額平均 | 標準差 | t | bootstrap 95% 區間 | 對基準的 beta | 扣 beta 後每日 alpha | alpha 的 t |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0050 買入持有 | +0.21% | 1.98% | 0.42 | -0.78%～+1.10% | 0.42 | -0.23% | -0.92 |
| 150 檔等權 | +0.48% | 2.16% | 0.89 | -0.58%～+1.48% | 0.39 | -0.15% | -0.53 |

- 讀法（推論）：超額報酬與零無法區分；贏基準的部分可以完全由低曝險解釋。帳戶日波動 1.57%，0050 是 3.04%。第一天帳戶還在建倉，beta 被壓低，正式分析要另外處理。
- 建議：賽後寫一支統計腳本，見 4.7。

**5. 模型記憶與比賽期間的關係還沒有寫成可查證的陳述**

- 文獻：The Memorization Problem、Look-Ahead-Bench。結論（研究摘要的推論）：最可靠的是評估期完全落在模型知識截止日之後。
- 現況（事實）：`src/etf_agent/evaluation/README.md` 寫「Agent 模型的知識截止約 2026-06」；比賽是 2026-10-27～11-27，晚於這個日期。但因為第 1 項，我們只有別名，沒有完整識別碼可以對照廠商文件。
- 讀法（推論）：如果截止日屬實，模型不可能記得比賽期間的行情，這比多數論文強。剩下的洩漏管道是人：Skill、策略教訓與設定是看著結果改的。
- 建議：論文裡分開寫「模型參數的記憶」（可排除，條件是查到截止日）與「人為適應」（無法排除）。

**6. 樣本太短**

- 現況（事實）：16 個已結算交易日，結束時約 24 個。專案自己的門檻是每個 horizon 至少 10 個完整決策日。
- 建議：全文只用描述性語言，不寫「顯著」。見 4.6。

**7. 基準不夠**

- 現況（事實）：有 0050 與 150 檔等權買入持有（`benchmark/service.py`），同費率、同成交價口徑，並有每日上漲與下跌捕捉（上漲 30%、下跌 49%，對 0050）。
- 缺的（意見）：
  - 曝險相同的基準，例如「0050 乘上帳戶每天的實際股票比例，其餘放現金」。沒有它，空頭行情裡任何低曝險策略都會贏。
  - 「沒有 LLM」的基準：同一套配置程式與風控，把 Agent 的意圖換成簡單規則或隨機，用來分離 LLM 的貢獻。
  - 主辦方排行榜的名次與分布，如果規則允許引用。
- 建議：賽後補，見 4.5。

**8. 設定在比賽中途被改過很多次**

- 現況（事實）：`config/policy_versions/` 有 42 個樣板，日期全在 11/09～11/17；`docs/status.md` 逐項記了時間、原因與方向，其中多項是加風險方向。10/27 之後有 39 個 commit。
- 影響（推論）：整段比賽不是「一個策略的 24 天」，而是「人看著結果持續調整的 24 天」。這是多重檢定問題，事後無法修正。
- 建議：論文附完整的設定變更時間線，並把績效依主要設定切換點分段列出。不要把最後一版設定的回放結果當成整段的成績。

**9. 重跑穩定性沒有量過**

- 現況（事實）：`evaluation/compare.py` 有 `pairwise_stability`，但 `artifacts/evaluation/` 只有一份 11/04 的回測格子，沒有任何重跑評測。
- 建議：賽後做，是論文最便宜的一張表。

**10. 信心分級的校準還沒有可報的數字**

## 4. 論文計畫

### 4.1 定位

- 類型：系統與經驗報告，加上一段即時、有第三方結算的紀錄。
- 不宣稱：贏市場、有 alpha、LLM 會選股、多 Agent 優於單 Agent。
- 宣稱：一套把「LLM 的判斷」與「可驗證的計算」切開的做法，在真實比賽裡跑了約 24 個交易日，每一步都可重算；以及這樣做之後實際觀察到什麼。
- 比賽成績不好時仍成立的理由：貢獻點是方法與紀錄。負面或不顯著的績效照實寫，反而呼應 FINSABER 與 Alpha Illusion 的主張。

### 4.2 標題候選

1. 把數字留給程式：一個可稽核的台股多 Agent 投組系統與 24 個交易日的即時紀錄
2. Deterministic Where Possible: An Auditable LLM Multi-Agent Portfolio System and a Live Competition Record on Taiwan Equities
3. What a Live, Hash-Sealed Record Can and Cannot Show: Lessons from an LLM Agent Fund Manager Competition

我的推薦是第 2 個：第 3 個更誠實，但像立場文。

### 4.3 貢獻點（每項都要能被查證）

1. 一個架構：Agent 只輸出列舉、文字與證據編號，所有數字由程式計算，驗證時整份重算。附契約與驗證器清單。
2. 一套時間一致與稽核機制：`available_at`、不可變快照、內容雜湊、版本閘門讓舊決策可逐位元重建。
3. 一段即時紀錄：晚於模型知識截止日（待確認）、由主辦方結算、含費稅與推論成本，並附完整的設定變更時間線。
4. 過程層的觀察：驗證失敗與修正的統計、意圖落地率、信心分級之後的表現。這類資料在現有文獻裡很少見（意見；我沒有系統性查過）。
5. 一份誠實的負面清單：哪些結論這份資料下不了，為什麼。

### 4.4 章節大綱

1. 引言：問題、文獻的批評、本文做了什麼與沒做什麼。
2. 相關研究：多 Agent 交易系統；評估方法的批評；修正循環與外部回饋；context 工程。
3. 比賽設定：規則（持股檔數、現金上限、單股上限、Active Share）、結算方式、交易池。
4. 系統設計：資料與快照；Agent 分工與隔離；證據種類；程式配置與風控；版本閘門。
5. 稽核與可重現性：封存內容、重建驗證、Skill 與程式版本指紋、已知缺口。
6. 評估設計：事先寫死的指標（3.1 的 B）、基準、統計方法、證據等級。
7. 結果：即時績效；過程指標；信心校準；穩定性；消融（標示為回放）。
8. 設定變更史與分段結果。
9. 威脅有效性。
10. 資料授權、倫理與 AI 使用聲明。
11. 結論與後續。

### 4.6 統計報告方式

- 主要數字用「對基準的每日超額報酬」，報平均、區間與天數，不報裸 Sharpe。24 個日報酬的年化 Sharpe 區間會寬到沒有意義，要報就同時寫區間並註明不可靠。
- 區間用 block bootstrap（區塊長度事先寫死），並列一般 bootstrap 作對照。
- 一定要報曝險調整後的結果，因為實現 beta 遠低於 1。
- 多日 horizon 用不重疊窗口，或明寫重疊。
- 用語：寫「在這 24 天裡觀察到」，不寫「顯著」「證明」「優於」。區間跨零就直接寫「無法與基準區分」。
- 試驗次數：如實報設定變更次數；不做 Deflated Sharpe 的正式計算（各次變更不獨立、也不是事先規劃的試驗，硬算沒有意義），改成文字說明。
- 所有指標在 11/27 之前寫進 3.1 的 B 文件；之後新增的分析一律標「事後探索」。

## 5. 請使用者決定的三題

**第 1 題：論文要不要公開程式與資料？**

- 選項一：公開程式、契約、驗證器與合成 fixture，資料只公開衍生統計與雜湊。
- 選項二：全部不公開，只寫論文。
- 選項三：連同封存資料一起公開。
- 我的推薦：**選項一**。不公開程式的話，「可稽核」這個主張別人無從檢查；選項三在授權沒逐項確認前不能做。

**第 2 題：賽後要不要花 token 做重跑穩定性與消融？**

- 粗估（推論）：穩定性約 72 次完整重跑；消融每個變體再乘一次。以 11/17 那次的估算金額推算，穩定性約 900 美元等值用量，五個變體的消融再多數倍。訂閱登入不另計費，但會占用量上限。
- 我的推薦：**做穩定性，消融只做兩個變體**（拿掉多空兩方、拿掉風險 Agent），而且只比決策差異、報酬當附錄。完整消融的成本高，24 天的樣本也撐不起報酬層的結論。

**第 3 題：比賽結束前要不要開 `trader_background_record`？**

- 開：剩下 8 天能留下「交易 Agent 看到哪一版策略教訓」的紀錄，對論文的人為適應分析有用。
- 不開：不增加任何流程風險。
- 我的推薦：**不開**。它會改變簡報的產生路徑，出錯會讓當天退成備援；而前 16 天已經沒有這份紀錄，只補 8 天對論文的幫助有限。賽後在評測環境開就夠了。3.1 的 C（模型識別碼）風險較低、不可替代，建議做。
