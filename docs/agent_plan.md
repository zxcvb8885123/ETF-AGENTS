# AI CUP 2026 Agent 開發規劃

本版本先聚焦三個核心模組：

```text
資料蒐集 → 策略決策 → 組合／資金風控
```

目標是每天自動完成一次：讀取資料、提出投資組合、通過競賽限制檢查，並產生可提交的交易清單與決策理由。

## 一、資料蒐集

### 目的

提供有日期、有來源、可回查的研究資料，讓策略模組只使用當時已經取得的資訊。

### 第一版資料

- **行情資料**：每日開盤、最高、最低、收盤、成交量與成交金額。
- **公司基本面**：月營收、財報、獲利與成長指標，保留公告時間。
- **新聞與事件**：公司重大訊息、產業新聞、法說會與風險事件，保留發布時間與來源。
- **競賽資料**：官方 150 檔股票、主動式 ETF 前十大持股、目前持倉、現金與 NAV。

### 模組產出

每檔股票產生一筆每日研究資料，至少包含：

```text
symbol, as_of, price_features, fundamental_features,
news_summary, risk_events, source_records
```

### 必要檢查

- 資料是否在決策時間前已發布。
- 股票是否屬於官方 150 檔交易池。
- 是否有缺值、重複資料或過期資料。
- 每一個新聞摘要是否能回溯到原始來源。

資料下載與清理由程式負責；LLM 可以整理新聞，但不能自行補猜缺失數據。

## 二、策略決策

### 目的

將研究資料轉成有證據的候選股票與目標配置，不直接繞過風控送出交易。

### 第一版方法：量化排序加事件分析

1. 計算趨勢、報酬、波動、成交量、營收成長等指標。
2. 對 150 檔股票計算可解釋的綜合分數。
3. 由 LLM 根據已取得的新聞與基本面資料整理利多、利空與風險。
4. 綜合量化分數與事件分析，產生候選清單。
5. 比較目前持倉與新提案，訊號沒有明顯變化時保留部位，降低交易成本。

### 模組產出

每個候選標的至少包含：

```text
symbol, action, score, target_weight,
reason, evidence, reduce_trigger
```

每個決策都要回答：

- 為什麼選這檔股票？
- 使用哪些資料作為依據？
- 什麼情況下要減碼或退出？

評分權重、換股門檻與持有週期先放在設定檔，之後用歷史資料回測調整。

## 三、組合／資金風控

### 目的

把策略提案轉成整股交易，並在提交前攔截所有競賽違規。

### 組合配置

- 每日持股 20–30 檔。
- 台積電（2330.TW）持股權重最高 25%。
- 其他單一股票權重最高 10%。
- 現金部位低於 NAV 的 25%；實作建議保留至 22% 以下的安全緩衝。
- 只允許官方 150 檔股票。
- 檢查 Active Share 不低於 20%。

### 資金計算

將目標權重轉成整張交易數量時，必須先計入：

- 買賣手續費 0.1425%。
- 賣出證交稅 0.3%。
- 交易後現金與持股權重。
- 目前持倉與當日可用現金。

初賽交易視為全數成交，成交價格採當日成交均價，因此提交前要做成交後模擬。

### 風控流程

```text
策略提案
  ↓
目標權重轉整股
  ↓
計入費用與稅額
  ↓
模擬成交後現金與持股
  ↓
檢查交易池、檔數、權重、現金、Active Share
  ↓
通過才產生交易書
```

檢查失敗時，系統應自動調整配置或退回策略模組重算，並記錄失敗原因。

### 後續要補的風控

- 價格上漲造成個股超過上限時的 5 個交易日調整機制。
- 最大回撤（MDD）監控。
- 交易前後的完整稽核紀錄。
- 報告內容與實際交易指令一致性檢查。

## 開發順序

1. 完成資料與目前持倉讀取。
2. 讓簡單量化策略產生候選清單。
3. 完成目標權重、整股數量與成交成本計算。
4. 接上 `CompetitionGuard.validate()`，所有不合規組合一律拒絕送件。
5. 加入新聞／事件分析與 LLM。
6. 用歷史資料測試報酬、交易成本與 MDD。

## 第一版驗收標準

每天可以自動完成：

```text
讀取資料 → 產生候選 → 建立組合 → 通過風控 → 產生交易清單與決策理由
```

每一次決策都要能回查使用的資料、模型輸出、風控結果與最終交易指令。
