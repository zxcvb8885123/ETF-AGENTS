# 目前狀態與限制

本頁記錄各功能目前是已接入、部分接入還是尚未接入，以及各來源的核准狀態。功能或來源狀態改變時請更新本頁。

- **已接入**：150 檔交易池、yfinance 研究日線、官方月營收／重大訊息／財報、虛擬帳本、每日決策鏈與可重建的中文報告。帳本使用 TWSE／TPEx 官方價量。
- **價格口徑**：Snapshot 的決策與帳本用價是同日官方原價（`execution_close_price`），研究指標用調整價；上市與上櫃官方歷史月行情皆可補抓。缺官方價時退回調整價，重放過去日期時含事後除權息調整，見[架構](architecture.md)。
- **已接入**：[台股恐懼貪婪指標](market_fear_greed.md)（期交所 VIX、Put/Call 比、FinMind 融資），`./start.sh daily` 在 cutoff 前抓取，由程式算出整體台股情緒；VIX 依使用者決定以非商業比賽研究用途核准，見[來源核對](source_audit/2026-10-23_market_fear_greed_sources.md)。
- **部分接入（來源已由使用者核准）**：[隔夜市場背景](overnight_market.md)（Yahoo Finance 的 ^GSPC、^IXIC、^SOX、台股代理 EWT／TSM、日韓指數 ^N225／^KS11、VIX，加期交所官網即時行情的台指期夜盤，`overnight-v1.1`）只給風險 Agent 現金姿態與最終報告當背景，不併入全市場情緒。`./start.sh daily` 在 cutoff 前抓取，`config/overnight_market_sources.json` 已核准（2026-10-30，apollo），空窗或抓取失敗時為 `unavailable`；改回未核准也是 `unavailable`。台指期夜盤只在台北 05:00 結束後才有（平日 21:00 的決策一律沒有）；期交所 OpenAPI 與 FinMind 的盤後資料落後一天，不能用，改用官網即時行情，**夜盤的日期與時間格式尚待明早 05:00 後第一次實抓驗證**，不符時會維持 `unavailable`。
- **已接入**：全市場新聞（中央社、自由時報 RSS，2026-10-23 核准）。`./start.sh daily` 在 cutoff 前抓取，每日決策由子 Agent 逐則標註後程式重建；至少 5 則獨立市場新聞、2 家媒體才算可用，否則改用恐懼貪婪指標。新聞步驟失敗不會讓整天失敗。
- **已接入**：FinMind 現金流量表（稅前淨利與官方損益表相符才用）進基本面分析；FinMind 單季財報經官方金額核對後，可補足去年同期累計財報（`cli/fundamental_repair.py`）。
- **已接入**：FinMind 個股新聞進事件分析師（只進公司事件通道，不代表全市場情緒）。只在決策截止時已核准時加入，且只用截止前最後一批抓取、連結網域在媒體白名單內的標題；事件報告升為 2.3。核對指令已於 2026-10-27 執行（`company_news_source_reviews` 有 `license_status=approved` 紀錄，證據為使用者自行判斷核准：僅標題、內部研究、不轉載，不是媒體書面同意），每日決策輸入自此帶入 `company_news_input`（2026-11-03 的 run 已確認）。見[來源核對](source_audit/2026-10-25_finmind_stock_news.md)。
- **已接入**：基本面指標期別改為逐檔「該股在 cutoff 前可得的最新一季」（比較期為同季去年）。由決策輸入的 `fundamental_period_policy: "per_symbol_latest_available_v1"` 啟用（新建立的 bundle 預設寫入）；沒有此欄位的舊 run 維持全快照 max(period) 的原重建行為。2026-11-03 實測舊做法因少數公司提早公布 Q3，132／150 檔被標 `CURRENT_STATEMENT_MISSING`。見[架構](architecture.md#基本面期別)。
- **已接入**：Snapshot 最新交易日有檔缺行情時仍退回前一個全池齊全日，但現在會在 `quality_flags` 留下資訊性旗標 `PRICE_DATE_FALLBACK_<最新日>_MISSING_<代號,…>`（不影響 `usable`）；未改為以最新日為準，因為決策輸入要求全池每檔都有最新行情，少一檔會讓整份決策 fail-closed，見[架構](architecture.md#快照交易日退回)。Yahoo 來源的 `trade_value`／`transactions` 在 Snapshot 層輸出 `null`（資料庫欄位 NOT NULL，仍以 0 佔位）。
- **已接入（2026-11-03，尚未實跑）**：交割口徑改為同日賣款可買替補（`config/decision_rules.json` 的 `reuse_sell_proceeds: true`，版本 `decision-rules-2026-11-03`、`available_at` 2026-11-03 12:00），與 `position_sizing` 的四個執行面閘門：買單依信心與名次取得現金、塵埃買單整筆取消（`cash_fit_order`，`RISK_CASH_FIT`）、現金達 25% 上限時留住出場持股（`cash_ceiling_fix`，`RISK_CASH_CEILING`）、有買進的股票單股封頂留 3%（`stock_limit_headroom`）、買單總額預留 3% 跳空（`buy_gap_reserve`）。舊 Policy／舊 run 沒有這些欄位，重建逐位元不變；同時修正 11/02 起 `effective_policy` 多出 `cash_buffer_floor: null` 鍵、使 11/03 前封存的 run 重建失敗的問題（現在只在 policy 有該欄位時才寫入）。見[架構](architecture.md#交割口徑與-2026-11-03-的執行面閘門)。
- **已接入（2026-11-03，尚未實跑）**：主辦方結果當結算地面真相。`VirtualAccountService.apply_decision` 與 `DailyAccountRunner`（`datapack_dir`＋`team_id`）讀結算日對應的 DataPack，`prev_day_orders.outcome=voided` 時把決策結算為無成交（`HOST_VOIDED`）並留下資料包雜湊；policy 的 `insufficient_funds_policy: "void_batch"` 讓模擬成交現金不足整批作廢。`cli/virtual_account.py daily／settle` 新增 `--datapack-dir`（預設 `var/datapack`）與 `--competition-profile`（預設 `config/competition_profile.json`，讀其 `team_id`），`./start.sh daily` 明確傳入兩者；結算發生在 `./start.sh daily` 內、早於 pipeline 的 datapack_gate，所以由這裡接上而不是 pipeline。讀不到 `team_id`（缺檔、缺欄位、空字串）時印明確訊息並維持純模擬成交，`var/datapack` 沒有對應本隊、結算日的資料包時也維持純模擬成交（不是錯誤）。CLI 層整合測試：`tests/virtual_account/test_cli_datapack_wiring.py`。
- **策略反思（2026-11-03）**：自動套用只放行降風險方向的旋鈕提案（每個旋鈕的方向寫在 `strategy_reflection/contracts.KNOBS.risk_reducing`），加風險或方向不明的提案只封存標 `needs_human`，需 `apply-pending --allow-risk-increase <reflection_id>`；校準／反思樣本門檻由 5 提高到 10 個完整決策日；影子回放改比對等權基準的超額並要求兩段不重疊子區間都不劣於基準；試用期絕對下限改 0.0005；`auto_apply` 維持 false（缺欄位視為 false）。回放、評測重跑與校準重算的報告都標 `evidence_grade: "replay_reference_only"`：只固定已封存的 Agent 意圖重算，不是對 LLM 判斷的前瞻驗證。
- **已接入**：主辦方資料包（DataPack）對帳。每日 `run` 在呼叫任何 Agent 前，把帳本持股與現金和資料包比對，對不上就停止；D-Plan 只在對帳一致（或明確略過）時產生，賣出不得超過資料包持股。見下方「主辦方資料包」。
- **已接入但仍需人工上傳**：每日流程在決策為 `approved`／`no_trade`、競賽設定已確認、帳本綁定與資料包對帳都通過時，自動建立 D-Plan v4.3 候選。主辦方伺服器驗證與上傳仍由人工執行；舊版回測已移除，現有的是評測的「便宜版回測」多日滾動回放（見 `src/etf_agent/evaluation/README.md`，不屬於決策鏈）。持股的換算價以已對帳 DataPack 收盤價為準，與 Snapshot 不同只記警告（`dplan.warnings`）。
- **已接入（尚未在真實排程中觸發）**：備援 D-Plan。決策被拒、D-Plan 被擋或流程失敗時，程式產生「全部續抱、無委託」的候選並走不可變封存（`artifacts/fallback_decisions/`），前提是持股 20–30 檔、現金 <25%、單股上限、全在 150 檔、DataPack 對帳 matched；不滿足就不產生並通知。不含 Agent 文字、不自動上傳。見[日常操作](operations.md#備援-d-plan決策被拒d-plan-被擋或流程失敗時)。
