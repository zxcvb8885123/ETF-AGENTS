# 每日決策架構

本文說明系統每天怎麼從資料走到一份「可供人工檢視的封存決策」。系統**不自動下單或送件**；最後是否上傳由人決定。

- 欄位細節以 `src/etf_agent/` 的契約與驗證程式為準，Agent 的工作說明（Skill）在 `tradeagent/`。
- 正文用白話；程式名稱、設定位置與旗標見[名稱對照表](glossary.md)。

## 一句話原則

**確定性的事交給程式，不確定的判斷才交給 LLM。** 程式負責算數字、查時間、核對引用、擋違規；LLM 只負責解讀、提出論點、說明取捨。

## 一天怎麼跑

```text
資料收集與快照 → 三位分析師（技術／基本面／事件與市場情緒）
  → 多頭、空頭研究員（同一份輸入、互相看不到對方）
  → 交易 Agent（取捨多空論點，給買賣意圖與信心）
      （第二輪：入選排序；`agent_swap` 啟用時再一輪換股提名，目前 v1 影子只封存、配置不讀）
  → 風險 Agent（給現金姿態與持股廣度）
  → 程式配置（權重、張數、費稅、情境、比賽限制檢查）
  → 封存決策與中文報告（人工檢視）
```

| 階段 | LLM 做什麼 | 程式做什麼 |
| --- | --- | --- |
| 資料 | 不做投資判斷 | 保存來源、抓取時間、可得時間與版本，建立不可變快照；截止時間後才出現的資料一律排除 |
| 分析師 | 逐檔給看法與有證據的發現；全市場情緒只整體給一次 | 算技術指標與財務比率、分批、檢查全部股票都有覆蓋；沒有可用來源時情緒直接標「無資料」 |
| 多空研究員 | 逐檔提出有證據的論點與強度 | 確認兩方讀同一份輸入、引用的證據屬於該股票、全池都有覆蓋 |
| 交易 | 把每個多空論點明確採納或否決，給買賣意圖與信心（高／中／低） | 確認每個論點剛好處理一次、沒有新增事實；算權重與張數 |
| 風險 | 配置前給現金姿態（積極／中性／防守）與持股廣度（集中／平衡／分散）；開啟 `cash_ratio_range` 時另給姿態內子等級（低／中／高） | 算回撤下限、費稅、現金、壓力情境；比賽硬規則不過就拒絕，修正最多 3 次 |

### 持股檔數與入選順序

持股廣度對應檔數：集中 22、平衡 26、分散 30（程式夾在比賽要求的 20～30 檔之間；集中設 22 是留兩檔緩衝給 Active Share 或不可交易剔除）。Agent 只選等級，不輸出檔數。

買進候選比檔數多時，依序決定誰入選：

1. 信心高低。
2. 同信心時，看交易 Agent 在第二輪給的名次（見下方「入選排序」）。
3. 仍相同，依股票代號。

沒有名次的舊封存改依「多頭論點減空頭論點的採納數」，再依 ATR 或代號。

持股已滿時，**未持有的新股只能用本次出場空出的名額**；已持有的加碼不受影響。名額由程式全域配對，交易 Agent 只收到名額背景，不指定誰換誰。另有人設定的「強制換股」：滿檔又沒人出場時，信心達「高」的新股可換掉「交易 Agent 標為續抱、且每週論點檢視判定被推翻、本次又有採納的空頭論點」的持股，每次最多 2 檔。

（`rotation.forced_swap` 已於 2026-11-10 隨 `agent_swap` v2 移除，以下是舊 Policy 重建時的行為。）啟用 `forced_swap.confirmation` 時，換股的現金可行性檢查與實際配置共用信心、名次及原有次排序規則；代號較前的換出持股賣款不足時，繼續檢查其他符合條件的持股，不因此取消後續可負擔的替換。未啟用 confirmation 的舊路徑不套用這項修正。

### 入選排序

交易 Agent 是分批執行的，各批看不到其他批的候選，所以只能給三級信心。批次合併後，交易 Agent 再做第二輪，一次看全部買進／加碼候選，**只在同信心等級內**排先後並附理由，不改信心、不新增事實、不輸出數字。每個等級只有一檔時，程式直接封存、不呼叫 Agent。

### 換股提名（`agent_swap`）

名額卡住（空名額少於想買的新股）時，交易 Agent 在入選排序之後多一次第二輪，提名「用哪檔新股換哪檔持股」並附依據，只有代號配對與文字、沒有數字；不需要提名時由程式直接封存 `not_needed`、不呼叫 Agent。提名失敗（驗證用盡 `exhausted`、暫時性錯誤 `unavailable`）只取消這個動作，其餘決策照常，硬性規則失敗仍整份拒絕。

- 目前（2026-11-10 起）是 **v1 影子期**：提名被封存並由 Finalizer 重建驗證，配置完全不讀提名；唯讀統計用 `cli/calibration.py shadow-swap`。
- v2（2026-11-10 20:10 已開啟）才讓程式依提名換股：換出者標 `exit`、旗標 `AGENT_SWAP`／`AGENT_SWAP_FILL`，不可行的對由程式取消（`AGENT_SWAP_CANCELLED:<原因>`），換出者不賣。

`agent_swap.exposure`（v2 已開啟）讓提名每對多 `purpose`，v2 依風險 Agent 的 `exposure_view` 取用曝險配對（見[曝險計畫](agent_led_exposure_plan.md)）。`agent_swap.quality_dip`（優質股第三階段，現行 v4 已開啟）讓 `purpose` 多一個 `quality_dip`，5c 另讀 `dip_facts` 驗結構，v2 配置時另加對數、買進權重、買進不超過賣款與轉向跡象的上限（見[優質股計畫](quality_dip_plan.md#104-第三階段實作紀錄2026-11-10第七版)）。

設計見[換股提名計畫](agent_nominated_rotation_plan.md)，契約見[決策鏈契約](decision-contracts.md#換股提名agent_swap)。

### 持股檢視（停損停利）

程式依帳戶成本與同快照行情，替每檔持股算出帳面報酬與近 5／20 日高點回落，交給交易 Agent 當事實。

- 不設死數字：賣、減碼或續抱由交易 Agent 判斷，重估條件要寫成之後看得到的事並含時間條件。
- 目前人只設了一條：帳面虧損達 15% 時，該持股必須被正視（續抱、加碼或不動作需同時採納多頭論點）；警示不是賣出指令。
- 比賽開帳或重建日的成本是當日收盤價，不是真實買價。
- 啟用相對交易池報酬（`context`）時，每檔多附相對全池的 5／20 日報酬與最新營收／財報的可得時間，幫助判斷是個股走弱還是大盤一起弱。
- 風險 Agent 不處理停損停利。

### 前次決策背景

程式把上一份決策對目前持股的意圖、信心與重估條件整理給交易 Agent，**只當背景**：

- 來源是同帳戶、已核准或無交易、目標交易時段嚴格早於本次的決策；同時段多份時，優先取帳本實際結算的那份，否則取截止時間最新者。
- 不是證據：沒有證據編號，交易 Agent 的文字不得引用；行動仍要由本次的多空論點支持。多空研究員看不到它。
- 沒有前次決策時標「無資料」，不算錯誤。

## 風控與配置規則

這些規則都由程式執行，不改寫交易 Agent 的原意圖，只在旗標欄位留下原因；仍無法滿足比賽硬規則時，由比賽限制檢查拒絕整份決策。

| 情況 | 程式做法 |
| --- | --- |
| 單股權重逼近上限 | 一律由程式按整張減碼；有買單的股票上限留 3% 空間 |
| 交易狀態非「可交易」 | 不建買單、續抱不賣 |
| 配置後持股少於 20 檔 | 依 ATR 由低到高，留住交易 Agent 標為出場的持股 |
| 現金逼近 25% 上限 | 同樣留住出場持股，直到低於上限 |
| 現金不足 | 依信心與名次分錢；新股只買到不足目標一半就整筆取消，不留零頭 |
| 買單總額 | 另預留 3% 跳空緩衝，避免開高被主辦方以資金不足整批作廢 |
| 單一產業超過 60% | 只減本次買進的增量，不強賣既有持股 |
| 換手超過 30% | 依信心低到高、ATR 高到低縮減買單；賣單本身就超過時留住出場持股 |
| 出場後 3 日內 | 不得再買回未持有的新股（已持有的加碼不受影響） |
| Active Share 低於 15% | 取消與最低那檔必備主動型 ETF 重疊最多的買進候選，最多重算 3 次，不賣既有持股 |
| 防守姿態 | 現金仍低於姿態緩衝（目前 20%；開啟 `cash_ratio_range` 時為所選子等級的比例）時，程式依 ATR 把持股減碼到緩衝，單次最多賣 NAV 的 25%。`drawdown_derisk` 版本：v1 整張進位可超過單次上限、同檔 add 會把股數加回（留下減碼旗標卻沒有賣單）；v2 進位不得超過上限；v3 另把被減碼的持股排除在本次加碼候選外，減碼後的股數就是上限，交易 Agent 標 add 也不加回、不建買單（再留一個 `RISK_DRAWDOWN` 旗標說明）。開啟 `high_conviction_cash_floor` 時觸發與目標改為緩衝 × floor_ratio（須 v3）。舊版本的決策逐位元維持原重建 |

現金緩衝：現金已低於姿態緩衝時，緩衝只擋買單動用原有現金，不擋用本次賣出收入買的替補，避免出場釋出的名額流失。

三個 2026-11-05 新增的版本閘門（正式設定：`limit_scaled_conviction` 與 `cash_ratio_range` 已開啟，`high_conviction_cash_floor` 與 `cash_ratio_range` 互斥而未開啟）（只在 Policy 帶欄位時生效，舊 Policy／舊 run 逐位元不變；計劃見 [`cash_buffer_high_conviction_plan.md`](cash_buffer_high_conviction_plan.md)、[`limit_aware_conviction_weights_plan.md`](limit_aware_conviction_weights_plan.md)、[`agent_cash_ratio_range_plan.md`](agent_cash_ratio_range_plan.md)）：

- 高信心現金下限 `high_conviction_cash_floor`（`floor_ratio`，建議 0.75）：高信心買單可動用原有現金到「姿態緩衝 × floor_ratio」（防守 15%、中性 7.5%、積極 2.25%），中低信心仍只能用賣款；防守減碼的觸發與目標同改為這條線（帶狀防守，避免隔日來回交易）；當日觸發減碼時不套用。動用時記 `RISK_CASH_SOFT_FLOOR`。份額預算不變。
- 高信心份額下限 `limit_scaled_conviction`（`alpha`，由人設定，建議 0.6）：高信心的目標份額至少為 alpha × 該股單股上限（台積電 25% → 15%，一般股 10% → 6%），預算足夠時高信心不因別檔被抬高而少於原式份額，必要份額總和超過預算時依入選名次填到用完；其餘照原式，`volatility_exponent` 為 0 時中信心不高於最小的高信心、低信心不高於最小的中信心，分不完的預算留作現金。兩者同時開啟時，名次第一的高信心股會先用掉高信心可動用的現金。
- 姿態內現金子等級 `cash_ratio_range`（`{version: v1, grid, max_daily_raise}`，第一階段；與 `high_conviction_cash_floor` 互斥，有 `drawdown_derisk` 時須 v3）：風險 Agent 除了姿態另選 `cash_grade`（lower／middle／upper，仍是列舉），現金比例 = `grid[姿態][子等級]`，取代三段階梯（建議格點：積極 3／5／8%、中性 8／10／13%、防守 15／18／21%；每點不高於 22%、姿態內相鄰差距不大於單日上限、姿態間不重疊）。單日只限制現金拉高：今日可選格點 ≤ max(該姿態最低格點, 前次比例 + `max_daily_raise`，建議 3pp)，往下不限；轉防守當天只到 15%，回撤強制防守也不放寬。前次比例由程式依前次決策的挑選規則綁進 Policy 的 `anchor`（前次 run 最終的現金緩衝；沒有前次 run 時為本次起始現金比例），只給風險 Agent 當背景、不可引用（風險理由出現前次 run_id、decision_id、proposal_id 或其內容雜湊即拒絕，含 decision_id／proposal_id 不帶前綴的完整摘要；比對有邊界，前後接英數或底線的較長 ID 不算）。超出一律退回重答（修正循環用盡即停止），不夾到邊界；修正循環的 `increase_cash_buffer` 也不得高於今日可選的最高格點。防守減碼目標就是所選比例。重建時以決策庫重讀前次 run 重算 anchor，沒有決策庫即拒絕。11-05 07:00 封存重放（`replay_reference_only`）：防守 lower 15% 時 6446 買 35,000 股、middle 18% 時 6446 仍被 `RISK_CASH_FIT` 取消。

這些規則多數由「版本閘門」控制：只由人在 `config/decision_policy.json` 開啟，策略反思不得改；沒有該欄位的舊決策逐位元維持原本的重建結果。逐項名稱見[名稱對照表](glossary.md)。

### 交割口徑與執行面規則

主辦方 DataPack 規格寫「交割以淨額計，同日賣出款也計入結算」，所以 `config/decision_rules.json` 自 2026-11-03 起設為賣款當日可用於買進。規則會封進每份決策，舊決策重建時讀封存的舊規則，不受現行檔影響。配置用的現金仍以已交割現金加本次賣出收入為底，比主辦方保守。

虛擬帳本結算時，若主辦方資料包顯示前日委託整批作廢，該決策結算為「無成交」；現金不足時也與主辦方一致，整批作廢而非逐張減少。每日流程尚未把資料包路徑與隊伍編號傳給結算程式，這條路徑還沒有真的用到（見 [status.md](status.md)）。

### 回撤控制

- 程式沿帳本歷史算 NAV 峰值與目前回撤。回撤達 5% 時現金姿態至少「中性」，達 15% 至少「防守」（2026-11-11 12:36 由 10% 放寬到 15%；目前數值以 [status.md](status.md#版本閘門啟用狀態) 為準）。
- 為避免在門檻附近天天切換：防守要回撤降到 11% 以下才回中性（原 7%，同日放寬，數值以 status.md 為準），中性要降到 3% 以下才解除。程式沿帳本歷史逐筆重放這個狀態。
- 風險 Agent 給的姿態比下限積極時，程式退回重答；Agent 不算回撤也不能放寬。
- 綁定時另存歷史的參照與雜湊，事後重建（CLI、D-Plan、交付、虛擬帳戶結算）都從帳本重算並比對；帳本讀不到或歷史不符一律拒絕。沒有參照的舊決策照原樣重建。

## 主辦方資料包對帳

- 每日在建立帳戶快照之後、呼叫任何 Agent 之前，讀取本隊、本目標交易日的 DataPack，與帳本比對持股股數（必須相同）與現金（容忍比率可調）。
- DataPack 是不受信任的外部檔：欄位嚴格白名單，結算未產生、身分或日期不符、對不上時一律停止。
- 結果寫入 `pipeline.json`；D-Plan 只接受「相符」或明確「略過」，並檢查賣出不超過資料包的可賣股數（應收配股不可賣）。
- 預設不一致就停止；明確加 `--rebase-to-datapack` 才以資料包重建帳本，並強制建立新快照，讓資料包時間早於決策截止時間，避免回填未來資訊。
- D-Plan 有已對帳 DataPack 時，股數換算、單股權重上限、淨流向容忍值與現金比例均使用同一份 `nav_tradable`；沒有官方 NAV 的明確略過流程仍用帳本 NAV，不代表已完成官方對帳。
- 實作在 `src/etf_agent/competition/datapack.py`；比賽第一天開戶與重建帳本在 `src/etf_agent/competition/account_opening.py`。

## 帳本結算

帳本若有前次已封存的決策，必須先用該決策指定成交日的 TWSE／TPEx 官方價量結算，才能建立新的「決策前帳戶快照」。主辦方結果是地面真相，結算規則見上方「交割口徑與執行面規則」。

歷史上櫃價量有缺口時，可用 `scripts/repair_pending_tpex_close.py` 從 TPEx 原頁補抓：抓取時間不回填成歷史可得時間，原文與雜湊都保留，仍須通過原帳本的結算驗證。

## 資料口徑

### 價格

| 欄位 | 用途 |
| --- | --- |
| `execution_close_price` | 決策與帳本用價：同日官方原價，附來源與證據編號 |
| `analysis_close_price` | 調整價，只供研究與技術指標 |

- 同日沒有官方價時，執行價為空，配置、風控與 D-Plan 退回調整價；重放過去日期時，這個退回價含事後除權息調整，是已知限制。
- 官方執行價只接受 `data/price_finality.py` 的 TWSE／TPEx 來源白名單；未知來源不會被標成官方，且與其他非官方來源一樣須在定案時間後抓取。未知來源仍可保存作研究資料，這項檢查不等同授權核准，也不取消上述執行價退回的既有限制。
- Yahoo 來源沒有成交金額與筆數，資料庫以 0 佔位，快照對 Yahoo 列輸出空值；帳本結算與校準只讀官方列，不受影響。

### 對應參賽策略文件的四類因子

參賽策略文件（`game_docs/ETF-AGENTS_AI_Agent_選股與決策策略_參賽格式.pdf`）寫的因子，都由程式計算後交給 Agent 判讀：

| 文件寫的 | 程式提供 | 交給誰 |
| --- | --- | --- |
| 基本面：營收、獲利、負債、現金流與期間比較 | 財務比率（逐檔取該股最新可得的一季）、月營收、現金流（營業現金流、資本支出、自由現金流、營業現金流對稅前淨利比率） | 基本面分析師 |
| 技術：5／20／60 日變化、均線、ATR 與下行波動 | 各期報酬、20／60 日均線與是否站上、14 日 ATR 比例、20 日下行波動 | 技術分析師 |
| 公司事件：影響、反證與待確認事項 | 重大訊息原文、同快照財報、截止時已核准的 FinMind 個股新聞標題（白名單媒體、截止前最後一批；新聞標「高」須指出重大訊息或另一家媒體佐證） | 事件分析師，再交給多空研究員 |
| 市場背景與風險：整體情緒、集中度、流動性、壓力情境 | 全市場情緒、產業曝險、流動性曝險、壓力情境、峰值回撤 | 風險 Agent |

### 基本面期別

- **新做法**（新建立的決策輸入預設）：逐檔取該股在截止時間前可得、損益表與資產負債表都齊的最新一季；都沒有齊全的季別就取任一報表的最新季（缺的報表照常標缺）；完全沒有財報的沿用全池最大期別（結果必為無資料，只為覆蓋全池）。比較期一律是去年同季。程式依期別分組計算再合併，並記錄每檔實際期別與雜湊，下游驗證整份重算。
- **舊做法**（舊決策輸入）：全快照最大期別當所有股票的當期，重建不變。2026-11-03 實測，舊做法在少數公司提早公布 Q3 時，其餘 132／150 檔被標「當期報表缺」。
- 不以法定公告期限推測期別（那是財報收集的驗收分母），以逐股實際可得性為準。

### 快照交易日退回

快照選「全池每檔都有定案行情的最新日」。最新日有任一檔缺行情時，整池退回前一個齊全日，並在品質旗標留下資訊性紀錄（列出缺哪些代號，超過 20 檔只列前 20 個）；資訊性旗標不影響快照可用性，其他旗標（缺行情、覆蓋不足、交易池驗證）仍會阻擋。

不改成「以最新日為準、缺檔逐檔標缺」，因為決策輸入要求全池每檔都有最新行情，少一檔會讓整份決策 fail-closed 而不是只擋該檔；退回前一日是較保守的降級。舊快照的旗標是封存值，不重算。

### 現金流與流動性

- FinMind 現金流量表經核對才使用：同期累計稅前淨利必須等於官方損益表，才轉成非官方來源的現金流文件；決策時再以同快照的官方稅前淨利核對一次。金融保險業、資料商未提供或核對不符時標為資料缺口。
- 比賽以當日成交均價結算，只有整批作廢或缺均價才不成交，所以壓力情境不另外依成交量限制成交。流動性曝險列出每筆委託佔 20 日均量的比例，超過 10% 或缺均量時標警示，只供風險審查參考，不是硬性規則。

## 證據規則

新建立的決策輸入預設啟用「證據種類」閘門（舊決策輸入不啟用，維持只檢查引用存在且屬該股的原驗證）：

- **證據種類由程式判定**，Agent 不填：行情、財報、公司基本資料、月營收、重大訊息、個股新聞、交易狀態、帳戶、市場層級（隔夜市場、全市場情緒、程式市場狀態）。
- **個股論點不得只靠市場層級證據**：至少一個證據要屬於該股；市場、帳戶、交易狀態證據只能補充，隔夜市場證據一律不得用於個股。
- **Agent 必須宣告種類**：多空論點與分析師發現各填一個種類（行情、財報、營收、重大訊息、新聞），主要依據的種類須相符；依據跨兩種時拆成兩筆。
- **現金姿態**至少引用一個市場層級證據；全市場情緒為負面時不得選「積極」；風險 Agent 的簡報不再附交易 Agent 的買進統計，避免群體思維。
- **驗證失敗的回饋用中性措辭**，同時列出「降級」與「補依據」兩種合法修法；重試時記錄前後差異，供事後稽核有沒有因回饋變積極。

Finalizer 與下游驗證遇到缺少必要輸入、引用不存在、版本不合、數值被改寫，一律拒絕。舊版買賣決策鏈（1.0）不再接受。

基本面工具另核對財報與其 `document:<id>` 來源證據的來源、URL、內容雜湊及可得／內容時間；證據本身也不得晚於 cutoff。缺少必要稽核欄位的外部或舊資料包會拒絕，不為了通過驗證補造證據。

證據的抓取時間允許晚於文件可得時間，但兩者皆須不晚於 cutoff；若證據另帶股票或可得時間，必須與文件一致。選配的舊 `perception_inputs` 則按決策交易池核對完整覆蓋：沒有新聞的股票仍須明確列為 unavailable，整體可降級，不能以空的 completed 結果冒充完成；這不改變目前主要的全市場新聞／恐懼貪婪通道。

### 日期資料夾

`artifacts/decisions/<date>/` 與 `artifacts/daily/<date>/` 的日期是**目標交易日**（台北時間），與 `artifacts/competition_d_plan/` 一致；晚上做隔天備案時就是隔天。缺目標時段（評測重跑、行事曆缺漏）才用執行當天。日期只是佈局，不影響編號、封印或雜湊；查找既有 run 一律全域掃描。

## 平行執行與耗時

`--max-workers N`（1～8，CLI 預設 8）讓分析師、多空研究員、交易 Agent 的各批同時執行；現金姿態與風險審查維持串行。平行只改變執行方式，不改簡報、驗證與配置：

- 結果依提交順序合併，不受完成先後影響；任一任務失敗就取消其餘並整體失敗，不用部分結果。
- `--resume` 沿用已存的原始輸出，平行與串行的續跑互通。
- `pipeline.json` 記錄各階段耗時；同時呼叫越多，越容易撞到訂閱用量或速率上限。

2026-10-22 實測（同帳戶同快照，各跑一次，僅供參考，8 尚未實測）：3 個並行約 929 秒、6 個並行約 601 秒，都核准且 30 筆委託。當時事件分析師 10 批，之後無重大訊息的股票改由程式輸出，批次會減少，需重新量測。

暫時性錯誤（逾時、無法啟動、非零結束、輸出不是 JSON）會間隔 30 秒再試一次，失敗嘗試記在執行紀錄；秘密外洩、未核准工具不重試；驗證失敗只走帶回饋的修正循環（最多 3 次）；等待加重跑會超過交件期限 08:55 時也不重試。

### 降低 token 的設定

詳見[降 token 說明](token_reduction_plan.md)。

- **技術面閘門**（預設開，`--no-technical-gate` 關閉）：趨勢一致（收盤同在兩條均線之上且各期報酬皆正，或同在之下且皆負）的股票只附動能與證據編號，其他與資料不足者附完整歷史；分析師仍對全部股票給看法，驗證不變。
- **分析師模型**：`--model`（交易、現金姿態、風險審查）在 Claude 預設 `opus`；`--analyst-model` 與 `--research-model` 預設 `sonnet`（`inherit` 沿用 `--model`）；實際模型記在執行紀錄。
- 交易簡報把完整帳戶持倉縮成現金／NAV、持股代號與檔數，本批逐股持有張數仍保留；完整帳戶快照與分析師原始報告繼續供驗證重建。

## 事件與市場情緒

- 重大公司事件保留在事件分析師報告，直接交給股票層級的多空研究；每日鏈不再另跑 Fact／Bull／Bear／Adjudicator，獨立事件研究與舊封存驗證仍可用，見[事件研究整合說明](integrated_event_analysis.md)。
- 決策截止時 FinMind 個股新聞已核准，資料包就加入個股新聞，事件報告升為 2.3，每則新聞須分類一次，見[事件研究整合說明](integrated_event_analysis.md#事件報告-23已核准個股新聞)。個股新聞只進公司事件通道，不進市場情緒。
- 全市場情緒優先用全市場新聞（`automation/market_news_stage.py`：截止前抓 RSS、子 Agent 逐則標註、程式重建，失敗時降級）；不可用時改用[台股恐懼貪婪指標](market_fear_greed.md)；兩者都不可用時維持「無資料」，不得用公司新聞或交易背景補值。範圍區分見[市場與公司事件範圍](event_market_scope.md)。
- [隔夜市場背景](overnight_market.md)是另一條只給風險 Agent 與最終報告的次級背景，不併入市場情緒、不給個股層級 Agent；來源已由使用者核准，夜盤只在台北 05:00 後的決策才有。

## 子 Agent 執行器

用 `--agent-cli claude|opencode|codex` 選擇，多空研究員另用 `--research-agent-cli` 指定（預設同主執行器）。輸出都過同一套驗證，續跑必須沿用原執行器。

| 執行器 | 驗證狀態 |
| --- | --- |
| Claude | 每日鏈使用中 |
| Codex | 可跑全部子 Agent，曾完成真實 150 檔每日鏈；但「暫存隔離版」（見下）尚未用真實 Codex 端到端跑過 |
| OpenCode | 通過本機唯讀、JSONL、預檢煙霧測試；尚未跑真實 150 檔端到端 |

讀檔邊界：

- 三者共用同一份拒讀清單（`.env*`、金鑰、憑證、含 credential／secret 的檔案等，含大小寫變體）。Claude 與 OpenCode 以權限設定強制；所有執行器的輸出若含專案 `.env*` 的值（長度 8 以上）一律拒絕。`*.pem`、`*.key` 等非 KEY=VALUE 檔案不在逐行掃描範圍，是已知差距。
- Codex 的唯讀沙箱只擋寫、不擋讀，所以要求互相隔離的多空任務預設拒絕在 Codex 上啟動，只在「研究階段輸出暫存」內放行：多空原始輸出只留記憶體，兩方都完成才一次寫入，任一失敗整批丟棄；續跑為全有或全無，否則要求新 run。
- 暫存是**時序隔離，不是權限隔離**：Codex 仍可讀整個專案，包含舊 run 的多空輸出；OpenCode 的互讀禁止也不擋舊 run；Claude 的拒讀樣式連舊 run 也擋，隔離最強。由 `tests/automation/test_research_staging.py` 守住不會被改動無聲破壞。
- 多空研究員的互讀禁止清單還涵蓋後段產物（辯論、意圖、交易決策、排序等），防止續跑時讀到。
- OpenCode 只准讀檔、不准執行命令或改檔，沒有可直接用的輸出結構限制，靠驗證程式與有限重試擋不合格結果。

## 旁觀者（不在決策鏈內）

- **校準**（`src/etf_agent/calibration/`）：只讀已封存決策與官方價量，記錄信心與多空強度，價格到齊後算前瞻報酬審計前日收盤與當日均價的差距，並統計買進意圖落地率（`cli/calibration.py intent-landing`，唯讀）。決策、自動化與風控都不匯入它。口徑見[校準旁觀者](../src/etf_agent/calibration/README.md)。
- **策略反思**（`src/etf_agent/strategy_reflection/`）：每週讓 Agent 提出策略旋鈕調整提案，經程式驗證與影子回放才改寫 `config/decision_policy.json`。
  - 自動套用只放行降風險方向；加風險或方向不明的提案只封存並標「需人處理」，須人用 `apply-pending --allow-risk-increase <reflection_id>` 套用。
  - 影子回放比的是對交易池等權基準的超額，且在兩段不重疊子區間都不得劣於基準或目前策略。回放只重算封存的 Agent 意圖，**不是對 LLM 判斷的前瞻驗證**，只有比賽期間的即時紀錄才算證據。
  - 版本閘門（逆波動配置、續抱優先、多空隔離等）不是旋鈕，不可調，由 `tests/strategy_reflection/test_design_guards.py` 守住。
  - 完整流程見[策略反思旁觀者](../src/etf_agent/strategy_reflection/README.md)。
