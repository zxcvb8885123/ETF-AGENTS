# 事件研究 Agent 計畫 V1

## 定位

本計畫是 [四層架構](agent_plan.md) 的第二層「研究與分析」。目標是讓 LLM 使用資料工具，找出官方交易池中有短期催化事件的股票，留下證據、反證與候選理由，再交由第三層完成配置與風控。

本文件為待實作設計。既有固定評分程式可作為比較基準；新的 Agent 工具循環、技能載入與事件資料來源仍需實作。

## 工作流程

```text
接收研究任務、資料截止時間與第一層快照
  → LLM 判斷需要研究哪些事件、缺少哪些資料
  → 呼叫工具查公告、歷史事件、基本面與行情
  → 閱讀結果，辨識新資訊、反證與資料衝突
  → 證據不足則補查；資料齊全或達到查詢上限則結束
  → 輸出 ResearchResult
  → 第三層配置與風控 → 第四層報告
```

控制器限制每次執行的工具次數、時間與 token 預算。達到上限仍缺關鍵證據時，輸出「待確認」及缺漏原因；工具失敗只允許有限次重試。

## Skill 與工具

規劃由 `skills/event-analysis/SKILL.md` 定義事件研究流程、證據要求、停止條件與輸出格式。控制器將技能載入 LLM，並提供以下工具；技能文件本身不執行抓取或入庫。

| 工具 | 用途 |
| --- | --- |
| `list_events` | 取得截止時間前、官方交易池內的事件候選 |
| `read_source` | 讀取保存的原始公告與發布時間 |
| `get_company_facts` | 查詢當時可用的營收、財報與展望比較資料 |
| `find_related_events` | 辨識舊消息、重複報導、後續更新與矛盾證據 |
| `get_price_features` | 取得程式計算的相對報酬、成交量與波動 |
| `search_news_candidates` | 查詢已保存的新聞候選、發布者、時間、連結、重複與誤配旗標 |

所有工具由程式強制套用 `decision_cutoff` 和股票範圍。資料收集與入庫由第一層負責；研究結果經格式與引用驗證後，由控制器保存。公告與工具回傳文字只作研究資料，不能改寫 Agent 指令或工具權限。新聞候選只能觸發補查或作次級證據；未連回可核對的原始報導或官方公告時，不得單獨形成進攻候選。

工具採細粒度且可組合的設計，參考 [stocks-scoring-agent](https://github.com/realmistic/stocks-scoring-agent) 將公司資料、盈餘趨勢、行情、新聞與文件分為不同工具的做法；但本專案不讓工具即時取得未保存資料後直接形成結論。每個研究工具只讀取第一層已版本化且符合截止時間的資料，並可在沒有 LLM 的情況下獨立測試。

## 分析任務

追蹤月營收、季報與法說、MSCI、公司重大訊息及有明確產業影響的總體事件。每個事件回答：

1. 發生什麼新變化，影響哪家公司？
2. 原始數字與比較基準是什麼？是否有反證？
3. 對該公司的影響偏多、偏空、中性或尚不確定？
4. 為何可能在比賽剩餘時間內反映？這是事實還是推論？
5. 行情是否已反映，是否需要等待價格確認？

LLM 負責事件理解、補查選擇與理由。營收增減、財報期間比較、動能、價格確認及後續權重與費稅由程式計算。情緒是研究的一項輸入；LLM 自報信心不能當作上漲機率，低信心也不等同中性。LLM 不直接輸出可執行的 `buy`／`sell`、最終持股權重或主觀 1～10 信心分數。FinBERT 可在評估階段作比較模型，第一版不要求同時部署。

## 輸出與下游銜接

`ResearchResult` 使用固定 schema 驗證，保存 `run_id`、`snapshot_id`、截止時間、模型與技能版本，並包含：

| 欄位 | 內容 |
| --- | --- |
| `event_id`／`symbol`／`event_type` | 事件、股票與事件類型 |
| `published_at`／`catalyst_date` | 公告發布時間及可能催化日期 |
| `direction`／`impact_mechanism` | 偏多、偏空、中性或不確定，以及影響機制 |
| `evidence_ids`／`counter_evidence_ids` | 支持與反證的來源 ID，不保存無來源斷言 |
| `fact_values`／`comparison_basis` | 經工具驗證的數字、單位、本期、前期及去年同期比較 |
| `price_confirmation` | 相對報酬、成交量、ATR、波動等程式結果及資料日期 |
| `risk_flags`／`uncertainties` | 資料衝突、來源缺漏、舊聞、追價及可交易性風險 |
| `research_status` | `candidate`、`pending` 或 `excluded`，以及理由 |
| `invalidation_signals` | 會使研究假設失效的後續公告或價格條件 |

欄位以 Pydantic 或等價 schema 驗證；列舉值、日期、股票代碼與引用由程式檢查。引用不存在、數字對不上或時間不合格的結果不得進入候選。後續動能研究提供防守候選，第三層整合兩類候選並產生買賣計畫。原有 65／75 分等固定門檻保留為待驗證基準，不要求 LLM 自行湊出總分。

## 開發順序

1. 第一層補齊歷史事件原文、發布時間、版本與查詢介面。
2. 實作可獨立測試的 `list_events`、`read_source`、`get_company_facts`、`find_related_events` 與 `get_price_features`。
3. 建立固定 `ResearchResult` schema，驗證引用、數字、列舉值及截止時間。
4. 實作技能載入、工具循環、預算限制及結果驗證。
5. 用人工標記事件測試公司辨識、影響方向、引用正確性與補查能力。
6. 接上動能、第三層風控及 [Agent 回測計畫](backtest_plan_v1.md)。

保存工具呼叫、回傳資料、結構化結果與簡短決策依據，供重播和稽核；不依賴模型未公開的內部推理。
