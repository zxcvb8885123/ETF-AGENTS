# 配置與輪動：權重、滿檔換股與風險修正

這份說明「持股怎麼配權重、滿檔後怎麼換股」目前的做法，以及哪些想法還沒接入。原本的診斷與設計稿（`sizing_rotation_v2_plan.md`）已併入這裡。決策整體流程見[每日決策架構](architecture.md)，規則總覽見[決策流程細節](decision-details.md)。

## 為什麼要做

2026-10-27／28 的決策 run 暴露三個問題：

| 問題 | 實際情形 |
| --- | --- |
| 防守股偏重 | 權重原本與波動度成反比，同信心等級內低波動股權重是高波動股的 4.6～4.8 倍。 |
| 滿檔後換不了股 | 持股 30 檔已滿，交易 Agent 對 11 檔新股給買進、卻沒讓任何持股出場，結果 13 檔候選全被擋下，委託數為 0。 |
| 修正通道是壞的 | 風險 Agent 要求修正時，輸出格式規定每個欄位至少一個字，但 Skill 又要求不適用的欄位填空字串，任何修正動作都過不了。 |

要注意的是，光改權重公式效果有限：把波動度完全拿掉，金融股也只從 26.0% 降到 21.9%。金融股偏重的主因是選股結果本身（30 檔裡有 7 檔金融），權重公式只是放大器。至於選股偏重，是分析團隊與多空研究的結論，不是程式偏好；若仍長期偏重，該檢討的是基本面分析師對獲利與現金流的權重（見[基本面成長訊號](fundamental_growth_signal_plan.md)）以及產業上限，屬策略層。

## 現況：已完成的部分

### 權重：可調的低波動偏好

權重 = 信心乘數 ÷ 波動度的 N 次方。N 為 1 時等於舊做法，N 為 0 時同信心等級內等權。舊方法（N 固定為 1）仍保留，舊 run 照舊能重建。目前正式設定 N = 0，信心乘數為高 1.5、中 0.6、低 0.3。這個 N 與「單次換股上限」可由策略反思微調（單次變 0.10，範圍 0～1），是反思的正式旋鈕。

### 入選順序

同信心等級內誰先入選，現行做法是交易 Agent 的第二輪排序（見[決策流程細節](decision-details.md)）。更早的備用規則仍在程式裡，供沒有排序的舊設定使用：

| 設定值 | 意思 |
| --- | --- |
| 低波動優先（預設） | 信心、支持數、ATR 低者優先、代號。 |
| 中性 | 信心、支持數、代號。 |
| 近期強勢優先 | 信心、支持數、近 20 日報酬高者優先、代號。 |

10-27 的實測顯示，這個規則當天只決定了最後 1 個名額，不是偏重主因；但在候選遠多於名額時，會有固定偏向低波動的潛在偏誤。

### 滿檔換股

交易 Agent 是分批平行執行的，各批看不到彼此的候選，所以「賣 X 換 Y」的配對無法交給 Agent，必須由程式全域做。做法如下：

| 項目 | 規則 |
| --- | --- |
| 誰決定出場 | 交易 Agent。出場須採納該股的空頭論點，Skill 明訂不得為騰名額而賣。 |
| 誰配對名額 | 程式。本次實際釋出的名額（被程式留住的出場、不可交易持股的出場不算），加上目標檔數之下本來就有的空位。 |
| 換股上限 | 每次最多 5 檔新股靠出場釋出的名額進場。 |
| 信心門檻 | 靠換股名額進場的新股，信心須不低於中等；否則被擋下並留下標記。目標之下的真正空位不受此限。 |
| 硬上限 | 配置後檔數永遠不超過比賽的最多持股數；沒有出場又沒有空位時，新股一律進不來。 |
| 廣度收窄 | 風險 Agent 選的持股廣度（例如 22）低於目前持股數時，只停止「淨增加」，不凍結既有持股的加碼與換股。舊做法會把加碼也一起凍住，這是一併修掉的隱藏缺陷。 |
| 強制換股 | 另有一條人設定的路徑，見[決策流程細節](decision-details.md)。 |

交易 Agent 在輸入中會看到程式算好的「名額脈絡」：目前持股數、上限、剩餘名額、換股規則，以及未持有股票的多頭強度分布與持股的空頭強度分布。這些是對共同輸入的統計，不是任何一批的輸出，也不是證據，沒有編號、不能引用，只當背景。它與其他分析輸入一起存進決策紀錄，Finalizer 事後整份重算比對（分析團隊輸入 2.3 版起；現行為 2.6）。

換股的成本很低：每次來回約付 0.585%（手續費兩邊加賣出稅），一天最多換幾檔再乘上每檔權重，約只占 NAV 的 0.06%；現行換手上限已調為 30%，也會約束過度換股。

### 風險 Agent 的修正通道

修正動作的輸出格式已放寬，改由程式依動作種類檢查：

| 動作 | 必填 | 必須留空 |
| --- | --- | --- |
| 移除候選 | 股票代號 | 數值 |
| 提高現金緩衝、降低單股上限、降低換手上限 | 0～1 的數值 | 股票代號 |

每個動作都須附理由。修正循環最多三次，用盡仍不過即由 Guard 拒絕。

### 向後相容

所有新欄位都是選配、版本固定，省略即走舊路徑，舊 run 逐位元重建不變：權重舊方法不經過次方運算；省略換股設定時名額算式與標記文案與舊版相同；分析團隊輸入的舊版本（2.0 起）驗證分支都保留。

## 尚未接入

| 想法 | 狀態 |
| --- | --- |
| 風險 Agent 的「要求既有持股出場」動作 | 尚未接入。目前風險 Agent 只能降低本提案的風險（移除買進候選、收緊三項數值），不能賣既有持股。當初的判斷是：金融股正是風險 Agent 最不會賣的標的，這個動作解決不了偏重，只能處理配置後才看得到的風險。若要做，必須同步更新 AGENTS.md、README、架構文件與風險 Skill，並限定只能因配置後風險而用；釋出的名額留給隔天，不在同一次修正內補買（否則修正鏈不再單調降風險）。 |
| 全池輪動回合 | 尚未接入。目前交易 Agent 每批只看得到本批持股的空頭論點；若實跑發現出場太少，可在各批之後多跑一回合，只允許把續抱改成減碼或出場。這會多一個 Agent 呼叫與一份契約，暫不做。 |
| 最短持有期 | 沒有。持股天數不在決策輸入裡，只靠前次決策背景和 Skill 提醒交易 Agent 自我檢查，程式沒有硬規則。 |
