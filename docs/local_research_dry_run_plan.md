# 本地 Agent 真實資料研究演練計畫

日期：2026-09-22。狀態：已執行；本輪有限範圍驗收通過。

## 目標與範圍

使用本地 Codex／Claude 工作階段、既有角色 Skill、CLI 與 Python Validator，完成一次真實資料的事件研究，交付可閱讀、可重建的 Research Report V0。這是既有研究工具的有限範圍整合演練，不代表 Data Agent M1～M4、完整 150 檔研究或正式決策主線已通過驗收。

本輪研究 3～5 個事件；不足時如實縮小範圍。情緒／分析師資料為選配，缺少合法真實 Provider 時標記 unavailable，報告明確降級。交付不含配置、權重、股數或訂單，也不稱為 DailyReport／D-Plan。

## 執行步驟

| 階段 | 工作 | 交付與通過條件 |
| --- | --- | --- |
| R0 資料盤點 | 檢查官方行情、月營收、重大訊息、財報與交易池；必要時用既有收集入口更新 | 保存來源狀態、版本、覆蓋及缺漏；不能把歷史終止日覆蓋當成完整交易日覆蓋 |
| R1 固定快照 | 收集完成後選定含時區 cutoff，建立不可變 ResearchSnapshot | 只使用 available_at 不晚於 cutoff 的資料；保存 snapshot_id、版本、來源證據與品質旗標 |
| R2 事件選取 | 預設查詢 cutoff 前 45 日事件，先保存完整候選清單，再依證據可驗證性篩選並按可得時間由新到舊選最多 5 件；同時間以 event_id 排序 | 記錄入選／排除理由與實際件數，不按預期利多利空挑選；不足 3 件時記錄原因，不補造事件 |
| R3 角色研究 | 讀取既有 event-analysis 與角色 Skill；Fact 整理證據，Bull／Bear 使用同一 FactPacket 獨立分析，最後交給 Adjudicator | 使用獨立工作階段或隔離的子 Agent；Bull／Bear 不接收對方輸出或含對方輸出的歷史；保存角色輸入、輸出與實際執行紀錄 |
| R4 驗證 | 透過 cli/event_research.py 執行 validate-debate、validate-result | 引用、時間、數字與角色依賴均通過；失敗保留診斷與修正紀錄，未通過者不交給報告 Builder |
| R5 報告 | 透過 cli/research_report.py build 產生同源 JSON／Markdown，再以 validate 重建驗證 | 呈現事實、多空推論、裁決、不確定性、研究範圍與缺漏；有市場認知資料時必須成對提供已驗證 result／bundle |
| R6 決策缺口盤點 | 核對下一輪需要的帳戶持倉、現金、交易狀態、競賽規則版本與基準資料 | 各項列出已有證據、缺漏、取得方式與阻擋階段；不以測試帳戶冒充正式帳戶 |

開始前先確認各 CLI 的 --help 與既有 Skill 所列契約。若補抓資料發生在 cutoff 後，不回填成當時已知：保留原快照，另建新 cutoff／新 run。

## 角色與執行紀錄

Fact 僅提供可驗證事實；Bull／Bear 的假設須明列；Adjudicator 不新增事實。MoM／YoY 是歷史比較，不能當成市場共識。沒有足夠方向證據時允許 uncertain，不強迫建立候選。

紀錄實際使用的程式 commit、Skill 版本或內容雜湊、工作階段／角色識別、工具呼叫與驗證結果。模型識別只有實際可取得時才保存，不猜測。既有 CLI 不提供的紀錄可先保存在演練附檔，不宣稱已有自動化控制器；若必須改動核心契約，先列明差異與測試範圍。

## 產物

每次演練使用獨立的 artifacts/local_research/<run_id>/，不覆寫既有範例或歷次產物。以下為預定保存內容，實際結構須符合既有 CLI 契約：

- 研究快照、資料覆蓋／缺漏紀錄及完整事件候選清單。
- 選取紀錄、Fact／Bull／Bear／Adjudicator 輸入輸出、DebateBundle 與 ResearchResult。
- ResearchReport JSON／Markdown、驗證輸出、exit code 與執行紀錄。
- 決策接入缺口清單及交付檔案雜湊清單。

資料庫中的原始回應與版本仍須保留；附檔需能追溯原始證據。雜湊清單是演練紀錄，不冒稱已通過自動化 Agent 的 PipelineRun 封存驗證。

## 停止與降級

- Snapshot 不可用、必要證據不存在、時間或版本不一致：停止受影響研究，保存失敗原因。
- 無法隔離 Bull／Bear 工作階段：停止辯論，不以同一上下文模擬兩次角色宣稱獨立。
- 選配情緒／共識缺少：不提供偽造 bundle，使用既有報告降級流程。
- 全部事件未通過驗證：交付診斷與缺口，不產生成功研究報告。
- 帳戶或規則缺少：本輪研究可完成，決策演練維持待接入。

## 驗收與後續

完成條件為至少一個真實事件通過雙重研究驗證、報告重建驗證通過、所有產物的 Snapshot／cutoff 一致，且範圍與缺漏可閱讀、數字與主張可追溯。只有 1～2 件時標記縮小範圍；零件不算完成。

只產生研究 artifacts 時執行既有產物驗證；若修改 Python、CLI、契約或 Skill，依 AGENTS.md 執行完整測試、compileall、diff check，必要時補 Skill 驗證。

本輪驗收後，依缺口清單安排 Portfolio Decision 真實資料演練。正式回測、前向驗證、D-Plan 與排程仍按原計畫完成前置驗收。本次僅證明有限的研究層真實資料演練可重建，並不代表已建立正式排程、正式決策或交易執行。
