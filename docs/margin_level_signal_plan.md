# 融資水位訊號計畫（恐懼貪婪指標第 4 項）

狀態：**程式與測試已完成（2026-11-04），`TWSE_TAIEX` 核准已寫入設定檔，尚待實跑 capture 驗證**（2026-11-04 資料來源已核對並經使用者核准做法 A'）。目前 `fear-greed-v1` 只有融資 5 日變化率，沒有「水位高低」。

## 要解決什麼

融資可以慢慢爬到很高，但 5 日變化很小；現行指標看不出來。要補一個「現在的融資水位，跟自己的歷史比排第幾名」的輸入。

## 為什麼不直接用融資餘額

融資餘額會隨市值長期上升（見 `contracts.py` 的 `MARGIN_CHANGE_DAYS` 註解）。今年的「高」可能只是五年前的「普通」。所以只能用「相對值」。

## 採用做法 A'

融資金額 ÷ 加權指數，取近 250 個交易日百分位。加權指數是市值的代理，能抵銷「市場變大」的影響。

- 融資金額：沿用已核准的 FinMind `TaiwanStockTotalMarginPurchaseShortSale`。
- 加權指數：FinMind `TaiwanStockPrice`（`data_id=TAIEX`），2025-01-02 起共 443 個交易日，免費可取。
- 融資維持率（原做法 B）在 FinMind 要付費，不採用。證交所網站條款禁止自動化擷取，也不採用。
- 來源核對見 [2026-11-04 核對](source_audit/2026-11-04_margin_level_sources.md)。

## 歷史回填與每日更新

做法：先一次抓齊歷史，之後每天只補當天。

1. **回填（只做一次，自動）**：不另設 `backfill` 指令。第一次 `capture` 沒有可沿用的先前抓取，會逐月抓近 14 個月加權指數，融資一次抓近 400 個日曆日，各存成不可變原始回應，`available_at` 是實際抓取時間。
2. **每日更新**：之後已收盤月份沿用先前保存的原始回應（保留原 `available_at`），只重抓當月與抓取時尚未收盤的月份；每次抓取自成一份完整資料包，不跨 run 合併。同日數值不一致即整份拒絕（既有行為）。
3. **回填之前的決策不能用它**：回填完成時間晚於 cutoff 的決策，這一項視為不可用，不回填到過去。
4. **回填不完整時**：該項不可用並寫入 `data_gaps`，不補值。
5. 來源分工（使用者表示兩種都可以）：預設指數用證交所 `FMTQIK`（約 12 次請求）、融資維持 FinMind（已核准）；若改全用證交所，融資需逐日抓約 250 次（每次間隔 3 秒）並重新核准。
6. 證交所條款頁目前查不到（猜的網址 404），`robots.txt` 未禁止 `/rwd/`；條款風險由使用者承擔，記在核對文件，與 VIX 相同。

## 設計

1. 新增指標 `FINMIND_MARGIN_LEVEL`（需要 `FINMIND_MARGIN` 與新來源 `FINMIND_TAIEX` 兩份原始回應，同日相除），方向 `greed`（水位越高越貪婪）。
2. 窗口用 250 個交易日，與現有 `WINDOW = 20` 分開，不改動既有三項。
3. 計分版本升為 `fear-greed-v2`。舊封存維持 v1 重建，逐位元不變。
4. `FINMIND_TAIEX` 需在 `config/market_fear_greed_sources.json` 新增核准紀錄；使用者已口頭核准，實作時請其確認後才寫入，程式不代簽。
5. 擷取範圍要拉長（現在 `capture_all` 的 `margin_days=120` 日曆日不夠 250 個交易日）。
6. 不得把今天補抓的歷史資料回填成過去可得：`available_at` 仍是抓取時間，cutoff 之後抓的不算。
7. 樣本不足、過期（> `MAX_STALE_DAYS`）一律該項不可用，不補值。
8. 不直接變成減碼／加碼規則；仍只是情緒輸入，由風險 Agent 當證據之一。

## 驗收

- 測試：cutoff 後資料、缺時區、樣本不足、同日數值衝突、原始回應被改、v1 舊封存重建不變。
- 跑 `pytest`、`compileall`、`git diff --check`（指令見 `AGENTS.md`）。
- 同步更新 `docs/market_fear_greed.md` 的指標表與限制。

## 風險與已知限制

- 融資水位是慢訊號，多頭市場可以高很久；單獨看會太早減碼。
- 250 日百分位只代表近一年的相對位置。
- 加入第 4 項會改變分數分布，區間門檻（25／45／55／75）可能需要重新檢視。
