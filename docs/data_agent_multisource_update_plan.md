# Data Agent 多來源更新計畫

日期：2026-09-23。狀態：規劃完成，尚未實作或取得第三方 Token。

## 1. 目標與架構

採用官方資料加 FinMind，補足 150 檔交易池的盤後價量、歷史基本面、現金流、籌碼及競賽基準。FinLab 第二階段選配，Fugle 暫不接入。

保留既有 Data Agent、SQLite、原始回應、Snapshot 與 Validator；核心放在 `src/etf_agent/data/`，本地 Codex／Claude 透過既有 Skill 使用 Python 工具。新增金融資料 API 不改變不串接模型 API 的架構。Data Agent 提供資料事實，下游決定方向、權重、股數及賣出條件。

## 3. 來源與金鑰

| 來源 | 分工 | 使用者需準備 |
| --- | --- | --- |
| TWSE／TPEx／MOPS | 官方行情、公告、財報、日曆、交易限制、公司行動 | 現有公開端點無須 Key；新增端點逐項核實 |
| FinMind | 優先接入：歷史基本面、現金流、籌碼及行情核對 | 註冊、驗證信箱、取得 Token，先免費帳號 |
| 主辦檔案／各投信官方網站 | 指定 ETF 持股及權重的原始證據 | 優先公開或主辦資料，逐項核實使用條件 |
| FinMind ETF 持股 | 集中取得 ETF 基準的候選方案 | sponsor 限定；先測覆蓋與授權，再評估訂閱 |
| FinLab | 第二來源、還原價及因子核對的選配 | 決定接入時再申請 Token／確認方案 |
| Yahoo／yfinance | 保留既有歷史研究備援 | 不作交易狀態及 ETF 基準證據 |
| Fugle | 延後至有盤中行情需求時評估 | 本版無須申請 |

FinMind 官方 quickstart 列出無 Token 300 requests/hour、註冊驗證後 Token 600/hour。執行仍以實際帳號權限及各資料集條件為準。[認證與額度](https://finmind.github.io/quickstart/)

FinMind 文件列出三大報表、營收及股利／除權息資料；籌碼文件列出法人、融資融券和主動 ETF 持股。ETF 每日持股需 sponsor，且有個別 ETF 缺資料，不能假設全數涵蓋競賽指定名單。[基本面文件](https://finmind.github.io/tutor/TaiwanMarket/Fundamental/)、[籌碼與 ETF 文件](https://finmind.github.io/tutor/TaiwanMarket/Chip/)

Fugle 現行基本行情方案註冊會員即可免費使用，仍須申請行情 API Key；行情與下單服務應分別判斷，不能概括為必須開證券戶。本版採盤後研究，因此延後。[行情方案](https://developer.fugle.tw/docs/pricing/)、[金鑰申請](https://developer.fugle.tw/docs/key/)

規劃以環境變數 `FINMIND_TOKEN` 讀取憑證；若採用 FinLab，由 adapter 將本專案 `FINLAB_API_TOKEN` 映射到其登入函式。這些設定目前尚未新增。Token 不進 Git、Snapshot、URL 日誌或研究 artifact，CLI 只顯示是否設定與權限測試結果。[FinLab 登入文件](https://finlab.finance/docs/reference/finlab/)

## 4. 執行階段

| 階段 | 工作 | 驗收成果 |
| --- | --- | --- |
| D0 來源核實 | 承接 TS0，來源／授權／權限／日期語意矩陣；6 上市＋6 上櫃抽樣，涵蓋金融業、缺值、代號承接 | 每個候選資料集有樣本、雜湊及核准／未核准原因；免費與付費能力分開 |
| D1 共用接入 | FinMind REST adapter、憑證遮罩、限流、分段回補、續傳、原始回應、版本化與 migration | 無 Token、錯 Token、超額、空回應及格式變更可診斷；重跑不重複資料、不覆寫版本 |
| D2 行情與日曆 | 版本化交易日曆、逐市場查詢、150 檔 2 年日線；原始價／還原價／公司行動分開 | 逐日覆蓋與來源核對報告；完整快照未齊時仍能查詢缺漏市場 |
| D3 決策必要資料 | 承接 TS5，正式交易限制與 150 檔狀態；ETF 比較選配 | 150 檔必要狀態可驗證；缺漏仍 blocked，ETF 權重缺漏不阻擋競賽上限 |
| D4 基本面與籌碼 | 營收 24 月、三大報表 8 季、法人／融資券 2 年；產業／估值按來源核實 | 固定分母覆蓋、單位期間映射、官方抽樣核對；下游契約升版後才消費新資料 |
| D5 研究補充 | 官方新聞、IR／法說文件、別名去重；FinLab 有明確缺口再做 PoC | 有來源的事件候選、日期及股票映射；市場共識維持獨立 Agent 管理 |
| D6 報告交接 | 結構化 CLI、資料就緒摘要、同 cutoff Snapshot 重建及工作流交接 | 150 檔資料包及缺口可追溯；分別驗收研究可用與正式決策可用 |

D0→D1→D2 優先執行；D3 的交易狀態來源核實從 D0 即開始，是正式報告前置；ETF 核實可後續選配，不等新聞或選配因子完成。D4 擴充研究深度，D5 不阻擋必要資料已齊的報告，D6 提供共同驗收出口。

本計畫補充 M1～M4：交易狀態沿用 TS0／TS5；D4 對應 M4 歷史支線；D5 對應 M2；D6 對應 M3。日曆與交易狀態提前驗收；ETF 基準另列選配。舊計畫「M4 不阻擋第一版」適用一般研究工具，不免除正式決策的必要輸入。

## 5. 必須修正的資料邏輯

1. 查詢與採用分開：本次 9/23 歷史回補在 HTTP 查詢前被最近完整日 9/22 擋下，不能據此證明歷史端點沒有 9/23。允許依市場日曆及收盤完成證據探測指定日；完整快照仍要求政策規定的同日覆蓋與時間一致性。
2. 來源優先序按日期、品質及用途判定：同日同口徑官方優先；過期官方價不覆蓋新鮮備援。FinMind 替代價必須有核准政策與來源標示；正式模式若限定官方價，仍維持阻擋。
3. 衝突隔離：保留雙方原始值，不取平均。價格容差依跳動單位，成交量先核對股／張及盤後口徑；重大差異不能只選最後抓到的來源。
4. 不可變版本：同內容去重並保留取得紀錄，更正新增版本；Snapshot 鎖定採用版本，重抓後舊 Snapshot 仍可重建。
5. 歷史可得性：保存 period_end、published_at、available_at、fetched_at 及時間證據。季度末、供應商 date 或法定期限不能直接充當可得時間。今日回補且缺歷史發布／版本證據的資料可供今日研究，不能回灌過去決策。
6. 財務與還原口徑：區分合併／個別、單季／累計、金融／一般業、幣別與倍率。原始收盤供股數／帳務計算；調整價供相容研究，另存還原方法及因子版本。
7. 選配 ETF 比較口徑：核實比較集合、全持股或前十大、現金及非股票資產處理；保留原始權重，不把部分持股正規化成 100%，不直接刪除交易池外基準持股。
8. 衍生指標由 Python 依版本化公式重算；供應商預先計算的指標只供核對，不能無條件覆寫結果。法人買超、歷史成長與市場共識維持不同資料類型。

## 6. 資料契約與操作

重用既有 raw payload、collection run、來源可行性報告與 Snapshot repository；新增資料以可遷移的領域表保存。D0 固定價格版本、交易日曆、公司行動、法人／融資券、ETF 持股及來源核對結果的 schema；跨來源主鍵含市場、標的、期間、來源、口徑及內容版本。Snapshot 升版時同步修改下游 Validator 與相容性測試。

規劃提供 `sources-status`、`probe-source`、`collect --dataset`、`backfill`、`coverage`、`reconcile`、`snapshot` 等 CLI 能力，實際命令 D1 定稿；這些不是目前已可執行的新命令。輸出包含 requested/complete/missing/conflict、資料日、cutoff、來源版本及缺漏取得方式；退出碼 0 完整、2 降級、1 失敗。

先 12 檔短期間，再擴至 150 檔。按每檔每表一請求估算，150 檔 × 6 表至少 900 次，尚未計分頁、重試與日期分段；不承諾一次免費額度可回補完。依權限採整日批次或逐股查詢，集中管理配額、預留餘量、快取與續傳。401／403 不反覆重試，超額保存等待狀態，暫時錯誤最多三次。

依各來源發布節奏與實際回傳日期判斷就緒，盤後不等於所有資料已發布。背景排程待手動流程驗收後另行啟用，本次不建立排程。

## 7. 驗收與交付

測試覆蓋截斷分頁、空回應、股票／單位錯配、時間越界、更正版本、跨市場日期不一致、來源衝突、付費表無權限、憑證遮罩、續傳與舊 Snapshot 重建。真實驗收採 12 檔 PoC→150 檔固定分母；新上市、停牌、無融資資格或承接差異須有不適用證據，不能暗自縮小分母。

程式實作後執行專案規定完整 unittest、compileall、git diff --check；修改 Skill 時另做相應驗證。本次只建立計畫及文件入口，執行 diff check。

交付來源矩陣、FinMind Provider、migration、契約／Validator、CLI、覆蓋／核對報告、新 Snapshot 與操作文件。Data Agent 完成後仍需同 cutoff 研究、10 億虛擬帳本、Decision run、競賽規則與 D-Plan 檢查，才可形成正式買賣報告。

目前先申請 [FinMind 帳號與 Token](https://finmindtrade.com/analysis/#/account/user)。sponsor 是否值得購買依 D0 覆蓋與使用權驗證決定；FinLab、Fugle 無須現在申請。
